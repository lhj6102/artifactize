# Chat ACP principles and invariants

Rules for Chat, ACP, storage, configuration and eval routing in `artifactize-core`.
Core principle: builders stay free; evals stay Artifactize-driven.

- **C-CHAT-ACP-UNIFIED**: agentic CLI Chat backends in `engine-core` unify on the single ACP layer (`src/acp/`) with native coding tools (`cwd = session.worktree`, `fs = false`, `terminal = false` client capabilities); no per-CLI bespoke Chat transports are added.
- **C-EVAL-ARTIFACTIZE-DRIVEN**: `engine-core` eval routing and execution never admit ACP backends and stay strictly on the Artifactize-driven harness (direct HTTP APIs and isolated `claude-agent`). `antigravity` remains statically rejected in `.artf` declarations and profile overrides, and runtime admission gives a targeted diagnostic when an unknown eval backend matches an ACP agent.
- **C-TRUST-BEFORE-WORKTREE**: enforce explicit `(agent_id, TrustScope, launcher_fingerprint)` consent (hashing executable bytes directly at the Trust gate before spawn, with built-in presets rejecting executables inside the worktree) before spawning or warm-reusing an ACP process in a worktree; run status, version and model probes only in empty private tempdirs; strip relative entries from child `PATH` for worktree spawns; never load ACP executable commands, arguments or environment from repository-committed files (`.artifactize`); never treat agent-self-reported `toolCall.kind` or `locations` as a security boundary.
- **C-ONE-TURN-OWNERSHIP**: isolate `engine-core`'s Verify MCP bridge to a one-turn transport (fresh loopback port and one-time capability token retired before the next turn can arm, rejecting `tools/call` outside an active turn and mapping agent-supplied `verify_start` keys into the disjoint internal `chat/` namespace with `request_args_hash` verification); serialize permission approval and cancellation in SQLite CAS (`PENDING` → `SELECTED` → `DELIVERING` → `DELIVERED` / `CANCELLED` / `EXPIRED`) against `Owner.token` and `stop_requested` across all local and remote Stop paths; decouple process supervision (`process_cancel`) from turn timeout and cancellation (`turn_cancel`), guarding warm reuse and `session/load` with atomic `generation`, `WarmOwner`, quiescence and `executable_sha256` checks.
- **C-ACP-EDGE-ISOLATION**: confine ACP JSON-RPC framing, protocol version 1 quirks, FIFO receive-order barriers, `configOptions` normalization, bounded output caps, sliding-window secret redaction and raw payloads inside `src/acp/`; converge all Chat engines onto typed `chat::Block` and `RunCard` without leaking raw ACP messages or unparsed `serde_json::Value` across `engine-core`'s public Chat API.
- **C-NO-SILENT-REGRESSION**: preserve existing sessions, transcripts and custom HTTP settings across schema and format upgrades (unidirectional v11 → v12 SQLite upgrade, edge deserialization of legacy `chat_sessions.data`, full-history normalization in `Conversation::history()`, and deterministic 128 KiB Handoff on cold ACP starts); abort rather than silently downgrading a user-selected `mode` when missing or mismatched; surface vendor or engine handoffs, config fallbacks and legacy transitions explicitly.
