## A. ChatGPT via official Sign in with ChatGPT + rig 0.43 OpenAI Responses — feasible with caveats
- Inference: bearer token to https://api.openai.com/v1/responses through rig's ordinary Responses client over a thin transport that accepts the route's untyped event stream (below); no fork/patch needed.
- Adapter must: set additional_params.store=false; stream; leave max_tokens/temperature unset; use SystemInstructionsPlacement::AllInstructions; treat `Ok` + Length/ContentFilter (response.incomplete) as failure; read response.error.code from the error body (normalized code is None); list models with a raw GET (rig list_models expects {data}, SIWC returns {models}; filter visibility=="list", use slug).
- Login (artifactize-owned): dynamic registration via auth.openai.com authorize (client_id=dynamic_agent_client -> issued oaiapp_ id), PKCE S256, loopback on 127.0.0.1 (no device flow), token exchange/refresh at auth.openai.com/api/accounts/oauth/token, revoke endpoint; access 1h, rotating refresh 30d; 0600 atomic storage; validate ID token via JWKS.
- Verified request contract (real SIWC account, 2026-10-04): `POST https://api.openai.com/v1/responses` with only `Authorization: Bearer`, `Content-Type: application/json` and rig's `Accept: text/event-stream`; no account, organization, originator or host-ID header (`ext_agent_host_id` goes only to the authorize request). Body: a listed `slug` as `model`, all system text in `instructions`, no system items in `input`, top-level function `tools`, `tool_choice`, `store:false`, `stream:true`, `reasoning.effort`, `include:["reasoning.encrypted_content"]`, `parallel_tool_calls:false`; nothing from the preview's unsupported list (`max_output_tokens`, `temperature`, `metadata`, `truncation`, `user`, ...).
- Real reply: HTTP 200 with **no `Content-Type` header**; the body is a standard Responses event stream (`response.created` ... `response.completed`) whose `response.model` is the exact requested slug. rig 0.43 accepts an untyped stream only for its Codex dialect, so the first real review failed with `HttpError: Invalid content type was returned: ""`. The adapter's transport now accepts an untyped 200 only when the body starts as an event stream; any other 200 fails with its HTTP status and a bounded body (provider `code: message` when it is JSON). 4xx/5xx keep status, code and message.
- Real run: `verify --eval yorkie/is-dog --force` (gpt-5.6-luna, reasoning low) ended GREEN in 3 turns with 2 tool calls; reported usage 4,909 tokens (4,746 input, 163 output, 11 reasoning).
- Risks: eligibility not promised (403 subscription_sharing_user_not_eligible).

## B. Claude via official `claude` CLI (2.1.287) subprocess — feasible with caveats
- Flags: -p --output-format stream-json --verbose, --model <full id>, --effort, --max-turns, --mcp-config + --strict-mcp-config, --tools "", --allowedTools mcp__..., --permission-mode dontAsk, --system-prompt, --setting-sources "", --disable-slash-commands, --no-session-persistence; settings claudeMdExcludes ["**"], autoMemoryEnabled false, disableAllHooks true, switchModelsOnFlag false. Never --bare (refuses OAuth).
- Verified with 2 real haiku calls: init tools [] / only mcp tool; model id in stream; MCP server enforced budget (call 1 executed, call 2 refused); cwd untouched.
- Caveats: effort may be silently lowered; tools execute before final message_delta (no exact pre-tool identity/usage gate); malformed/unknown calls never reach MCP; repair = second tools-disabled invocation; cancel by process-group SIGTERM (exit 143).
- Policy: allowed for the unmodified binary with the user's own login; artifactize must not collect/store/intermediate Claude tokens or add its own Claude.ai login.

### P5.6 implementation contract (2026-10-04)

Rechecked `/home/user/.local/bin/claude --help` and official [CLI reference](https://code.claude.com/docs/en/cli-reference), [headless](https://code.claude.com/docs/en/headless), [model config](https://code.claude.com/docs/en/model-config), [environment variables](https://code.claude.com/docs/en/env-vars) and [settings reference](https://code.claude.com/docs/en/settings-reference). Docs win when help omits a documented option.

- Launch uses the plan's flags plus `--include-partial-messages`, `--disable-slash-commands`, `--no-chrome`, replacement `--system-prompt`, and inline settings `claudeMdExcludes:["**"]`, `autoMemoryEnabled:false`, `disableAllHooks:true`, `switchModelsOnFlag:false`, `fallbackModel:[]`. No `--bare`, resume, model fallback flag, or patched CLI. Explicit reasoning is passed unchanged; omitted reasoning becomes `high`. Use a full model ID, not an alias or a context suffix absent from the returned model identity.
- Real HOME and Claude config/OAuth/mTLS authentication environment remain for the CLI itself; artifactize never reads or copies its credential files. Provider/API-key/model/effort/thinking/plugin/session/retry overrides and proxy variables are removed. No API-key billing fallback. Retry count and non-streaming timeout retries are zero; non-streaming, model-access and legacy-remap fallbacks are disabled. `ENABLE_TOOL_SEARCH=false` prevents an additional tool-discovery tool from changing the exact surface. Managed policy still applies; exposed tool/model discrepancies fail closed.
- Parse NDJSON as it arrives (8 MiB per line, 32 MiB per invocation), require init and successful terminal result plus exit 0, check all exposed assistant/init/modelUsage model identities, and reject incomplete stops. Deduplicate usage by message ID, take output/stop from message_delta, retain terminal usage/modelUsage/total_cost_usd separately, and count input/output/cache tokens once for the budget. No CLI invocation replay, even before output; zero retries is within the plan's at-most-two bound. Effort is not reliably echoed and can be lowered by CLI/model/managed policy: requested effort is not actual-effort attestation.
- Exact init-tool set has one documented exception: optional `EndConversation` when the registered MCP tool set is nonempty. The official CLI reference says neither `--tools` nor `--disallowedTools EndConversation` can remove it while any other tool remains. This control-only tool cannot observe or modify the workspace; all other builtins/connectors/undeclared MCP tools fail closed. Repair requires the empty set.
- **Turn-gate relaxation:** MCP `tools/call` has a JSON-RPC request ID, not the Anthropic assistant-turn/tool-use identity. The CLI may issue it before the observer receives model/usage, and final output usage arrives at message_delta. An exact matching turn permit would require a separate interception/correlation protocol and could deadlock the CLI. P5.6 therefore does not add one. Token/model violations cancel on receipt, but cannot undo earlier observations. maxToolCalls is enforced atomically in the existing persisted MCP admission counter; malformed/unknown calls rejected by the CLI are absent from that audit. A recorded budget refusal makes the review ERROR even if Claude returns a valid verdict.
- Repair is one new process with inline `{"mcpServers":{}}`, strict MCP, no builtin tools, same model/effort and remaining original deadline/token budget. It receives the original prompt, prior assistant/tool-result context and a fixed format error, never a preferred verdict. A second invalid result is ERROR.
- Ctrl-C/deadline/fail-closed parsing sends SIGTERM to the CLI process group, gives MCP up to two seconds to cancel/reap its separately supervised tool groups, then SIGKILLs remaining CLI descendants. A normal leader exit also cleans descendants. There are no turn-permit waits to release. Trusted programs can escape process groups; this is supervision, not a sandbox.
- Output layout: `state/runs/<run-id>/claude-<execution-id>/{mcp-config.json,mcp-manifest.json,mcp.lock}`. Declared commands temporarily add `tool-<random>/runtime-<random>/{home,tmp,output,cache}` below it; normal tool cleanup removes those trees. No private Claude HOME, raw stream/transcript file or repair output file. The whole `claude-*` subtree is disposable after the Run finishes; results, usage and MCP audit are retained in SQLite. Claude-owned state in the user's real HOME is never pruned by artifactize.
