# Desktop app: user journeys

What a person can do in the desktop app, from the app's real behaviour. Each journey has an id
(`J-...`) and ends in something visible. It is the artifactize app of this
machine, not of one repository: one screen shows every live branch of every project with Runs
on this machine and every Human review waiting for a person. It shows and changes the same state
as the `artifactize` CLI; a change made by either shows in the other.

Hovering only highlights what is under the pointer: no popup, summary, tooltip or menu opens on
hover, and information opens only on a click. A pane is never wider than its place: its width
is set by the layout or by a drag, never by what it shows, and what it shows wraps or scrolls in
its own box. The Detail's tabs show as rounded chips, the chosen one filled; a choice within a
tab, such as its Summary or its log, shows as plain text, the chosen one dark and bold and the
other light.

## Window

- **J-LAUNCH**: the app opens on its one screen, the left pane beside the main area. The window is titled "Artifactize". Started with `--repo PATH` it selects that branch; with `review ID` it opens that review, and with `review` alone the newest waiting one; with `graph --repo PATH` (also the declared Human `graph` tool) it shows that branch's Current.
- **J-SETTINGS**: Ctrl+, or the Settings button opens Settings as a modal over the screen; Esc, its Close or the button again closes it, the screen beneath as it was. Settings has two tabs, Providers and Remote.
- **J-PALETTE**: Ctrl+K or the palette button opens the command palette; typing filters commands, Enter runs one, Esc closes it. It opens again after any use.
- **J-HELP**: `?` lists the keys of what has focus.
- **J-REFRESH**: Ctrl+R or F5 reloads the state from disk, scans the branches again and, on a Current, scans its worktree again.
- **J-QUIT**: `q` outside a field, or closing the window, quits. With Human review claims held by this window it asks first: Esc stays, `u` releases the claims and quits.
- **J-OPEN-ID**: the palette's "Open a request by ID", or Ctrl+O, opens a saved request in the main area: a waiting Human review actionable, any other request read-only.
- **J-UPDATE**: when a newer stable release of artifactize is out, the header shows `{version} available` before Settings. A click on it opens a dialog with the running and the new version and how to update the way this app was installed: the command to run, as text that can be selected and copied, or the file to download and install by hand; when the way is unknown, the release page. A link opens in the browser; Esc or Close closes the dialog. A Microsoft Store install never shows it: the Store updates the app. The app looks up the latest release on GitHub when it starts and once a day while it runs, the same lookup `artifactize doctor` reuses, and never downloads or installs anything itself.

## Left pane

- **J-PANE**: the left side is one column: a search field at the top, the branches below it, and the reviews waiting for a person at the bottom. The divider between it and the main area is always shown. There is no Scope heading, no Runs list and no screen switch.
- **J-BRANCHES**: each branch reads as its project and branch, `artifactize / feat/x`, the branch in bold and the project quieter: a Git worktree that exists now with the branch it has checked out (a detached one by its folder's name), or a folder outside Git that exists now and holds its declarations. Its projects are those with Runs on this machine and the one the app was started for with `--repo` or `graph --repo`; a worktree or folder that was removed, or whose worktree Git no longer lists, is not shown, and worktrees added or removed appear or go within seconds, without a reload. Who ran a Run, an agent session or a person, makes no entry of its own: a branch's Runs are the Runs of that project on that branch, from whichever folder they ran in.
- **J-BRANCH-RUNS**: a branch is folded or expanded, any number expanded at once, with a chevron before its name. Folded, its newest Run sits under its name, a dot in its status colour, its status word and its age on the right (a running one its time so far), or `No Runs yet`. Expanded, its timeline sits there instead, newest first: one entry per Run, its status dot, status word and age, its Run ID below, the dots joined by a line; while a Run is in progress on the branch the timeline starts with it, otherwise with the **Current**, a ring reading `Working tree`. **Older runs** at its end brings older Runs in below the oldest. A click on a branch expands it and shows its newest entry; a click on its chevron only expands or folds it; a click on an entry shows that one in the main area, the shown entry in a grey pill. The branch the app was started for starts expanded.
- **J-BRANCH-STAR**: a star at the end of a branch's name line, faint until it is on, pins it: starred branches are listed before the others, each group in the search's order, and stay starred for every later monitor of this machine's user until the star is taken away.
- **J-PANE-SEARCH**: `/` or Ctrl+F focuses the search, whose starting query is `sort:recent`. Free text and `key:value` terms must all match: free text matches part of a project, a branch or a waiting review's eval, `repo:` and `branch:` part of that one field, and they narrow the branches and the waiting reviews alike; `sort:recent` puts the branch with the most recent Run first and branches without Runs last, `sort:name` orders them by project and branch. Suggestions complete keys and values; Esc closes suggestions, then puts back `sort:recent`, then returns to the list.
- **J-PANE-NAVIGATE**: ↑ ↓ or `j`/`k` move through the branches, the timelines of expanded branches and then the waiting reviews, the list scrolling to show the selection; a branch shows its newest entry and a timeline entry shows itself. → expands the selected branch or enters its timeline, ← steps back out of it or folds the branch, and ↓ past a timeline's oldest entry brings older Runs first. Enter moves into the main area, and Esc there, with no Detail open, returns to the pane.
- **J-WAITING**: the waiting Human reviews of every repository on this machine, those of removed branches included, newest at the top, each with its eval, its project and branch, how long it waits and who claimed it. With none waiting they are a thin bar at the bottom of the pane reading `(0)`; each waiting review adds a row and the area grows upward like a stack, up to half of the pane's height, beyond which the list scrolls. A click or Enter on one opens the review in the main area.
- **J-LIVE**: a change made by another process (a new Run, a result, a claim, a submission, a worktree added or removed) appears in the open app without a reload.
- **J-RESIZE**: the divider between the pane and the main area can be dragged to resize them; the split stays as dragged whatever the main area shows. Dragging the Detail's left edge sets its width, between a readable column and leaving some graph visible, never over the left pane; the Detail keeps that width when opened again and in the next launch. Hovering a divider or the edge shows only the resize cursor.

## Main area

- **J-MAIN-RUN**: a Run chosen in the pane fills the main area with the graph of its Artifacts and their verdicts, under the Run's headline and what needs attention. With nothing chosen, while loading, on an error or with an empty graph the graph's place stays and says so. What went wrong, such as Runs that cannot be read, shows as one line in the main area's header without moving or hiding the graph; a click on it shows it in full.
- **J-MAIN-CURRENT**: a branch's Current scans its worktree as it is now, as `artifactize status` does, and draws the graph of its current declarations, each Artifact coloured, as a Run's Artifacts are, by whether it is reusable (every eval's result would be reused without evaluation), needs evaluation, waits or is blocked, its node showing only its name (read aloud, it says which, with how many of its evals would run); its header says when it was scanned. It scans again when chosen again, on Refresh and when a Run of the branch ends. Expanding Structure and evaluation criteria shows every criterion and labeled relation as text.
- **J-MAIN-REVIEW**: a waiting review opened from the pane fills the main area as a Human review (J-HUMAN-LAYOUT), its eval and Artifact above it; choosing a branch or a timeline entry leaves it without closing it.

## Detail

Both graphs, a Run's and the Current, take the pointer: Tab reaches their Artifacts and Enter on one does what a click does; they have no other keys of their own.

- **J-DETAIL**: a click on an Artifact opens its Detail, floating over the graph docked toward its right edge with a gap, never beside the left pane, the graph staying visible behind it. The Detail's tabs read as a path, `[Artifact icon] {name} / [eval] [eval] …`: the Artifact's own chip, the Artifact icon before its name, read aloud as "Artifact {name}"; only the name is cut short when long (the Detail's title shows it whole), then a `/`, then one chip per eval showing its verdict's glyph and colour, on a Current whether it would run or be reused; an Artifact without evals has its own chip only, without the `/`. Eval chips that do not fit on one line wrap onto the next, within the Detail; the `/` stays with the Artifact's chip. Close is the Detail's one control of its own. A click on another Artifact shows that Artifact's Detail; a click on the graph's background, Close or Esc closes it, after first cancelling a Human review's running work and then leaving its form (J-HUMAN-ESC). A click on a Run's headline opens the Run's Detail. Everything in the Detail, transcript and log lines, long words and code included, stays within its width.
- **J-DETAIL-NEIGHBOURS**: the Artifact's chip is shown first. It draws the Artifact between its neighbours with the graph's nodes and edges, the Artifacts its evals use on its left and those whose evals use it on its right; the drawing does not pan, zoom or drag, and a click on a neighbour opens that neighbour's Detail. Below it, the Artifact's evals with their verdicts (a click on one shows its tab), its Human tools (J-DETAIL-TOOLS) and its path; every other fact, what it waits for included, folds under Debug.
- **J-DETAIL-TOOLS**: an Artifact's chip lists the Human tools the Artifact declares, with the look and behaviour of a Human review's Tools and Tool log (J-HUMAN-TOOL, J-HUMAN-LOG): a click on a tool's `▶` runs it at once in the branch's worktree as it is now, whichever Run is shown, with no claim, and records nothing as a review's evidence. Its runs show in the Artifact's Tool log while the app runs. The graph's nodes carry no tool buttons.
- **J-DETAIL-SUMMARY**: an eval's tab shows its Summary: its status, beside it in grey what running it took and spent (time, tokens in `k` or `M`, model) or what reuse saved; its instruction; its result, each owner field by name and a list as numbered items; then Execution options, Execution metadata and Fingerprint when present; every other fact, what it waits for included, folds under Debug. On a Current it shows whether the eval would run or be reused and why, and the result it would reuse. An eval with a log switches below the tabs between its Summary, shown first, and its log, a plain text choice a level below the tabs: an Agent eval's Agent log (its transcript, with its own scrollbar) or a runtime eval's Runtime log (its saved output). A Human eval's tab in a Run holds its review and sign-off.
- **J-GRAPH-COLOURS**: nodes and edges are coloured by verdict (GREEN, running or waiting for a Human, waiting, RED, ERROR, blocked), on a Current by what would happen (reused, would run, waiting, blocked), and recolour in place when a result or scan arrives.
- **J-GRAPH-LARGE**: a graph too large to draw at once stays navigable: panning or zooming the camera draws the Artifacts it brings into view.
- **J-GRAPH-CAMERA**: a graph shows whole when it first appears. From then on only the person moves its camera, by panning, zooming or Fit View: opening, switching, resizing or closing the Detail, a result or scan arriving and a new layout never zoom or pan it.

## Human review

- **J-HUMAN-CLAIM**: `c` claims a waiting Human review for this reviewer; `u` releases it. A claim made elsewhere shows as taken.
- **J-HUMAN-LAYOUT**: a Human review reads top to bottom as its instruction, the Tools, their Tool log and the Result.
- **J-HUMAN-TOOL**: the Tools are grouped by the Artifact that declares them, the reviewed one first, each a `▶` button; after a claim a click on it runs it at once. A launch tool opens its application and returns at once; a failing tool shows its error.
- **J-HUMAN-LOG**: every run of the review shows in the Tool log as it happens: `▶ HH:MM:SS · operation · Artifact`, then each line the tool prints, stderr in red, then its end line (`■ exit 0`, `■ launched`, `■ done`, `■ error: …`). A launched application's lines keep arriving under its own run until it exits. The log is monospace, wraps, scrolls on its own and follows its newest line unless the reader scrolled up; its text can be selected and copied into the result. A submission clears it.
- **J-HUMAN-GREEN**: after a claim `g` opens the GREEN form built from the eval's pass schema; Ctrl+S submits. The completed result stays open.
- **J-HUMAN-RED**: `r` opens the RED form; a result that fails its schema is not submitted, the failing path is shown and the form stays correctable. Ctrl+G and Ctrl+R switch the verdict while editing.
- **J-HUMAN-FORM**: the form shows text, number, true/false and choice fields, a list of text with `+ Add` and `✕` per item, and repeated groups of fields with `+ Add` for a group and `✕` per group, one group always left to type in. Constants are filled in and not shown; `*` marks a required field and an empty optional one says Optional in grey. There is no JSON editor.
- **J-HUMAN-TEXT**: text fields take any language, including Korean composed by an input method; no key typed during a composition triggers a shortcut.
- **J-HUMAN-ESC**: Esc cancels running work, then leaves the form, then leaves the Detail or, for a review opened from the pane, returns to the pane.

## Settings

- **J-SET-PROVIDERS**: the Providers tab lists the built-in providers vertically on the left (Codex, OpenAI, Anthropic, Gemini), then the custom providers by name, then **+ Custom provider** at the bottom. Choosing one shows its setup on the right.
- **J-SET-CODEX**: Codex signs in to or out of the ChatGPT account through the browser; when the browser cannot return, the redirect URL can be pasted; a sign-in in progress can be cancelled.
- **J-SET-KEY**: OpenAI, Anthropic and Gemini each show whether their key is set, from the environment (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY`) or saved here, never its value. A key can be pasted and saved, or removed; a set environment variable is used first.
- **J-SET-CUSTOM**: **+ Custom provider** adds a provider with a name: an alias of a built-in provider, used with its sign-in or key, or an endpoint with its API (OpenAI Responses, OpenAI Chat Completions, Anthropic Messages or Gemini), base URL and optional key. Any number can be added; a custom provider can be changed or removed. An eval uses it by its name in `backend`.
- **J-SET-MODELS**: a provider's setup lists the models it offers.
- **J-SET-REMOTE**: the Remote tab signs in to a shared review store with its URL, share level and token, shows its status, pushes results (or a dry run), and signs out.
