# Desktop app: user journeys

What a person can do in the desktop app, from the app's real behaviour. Each journey has an id
(`J-...`) and ends in something visible. It is the artifactize app of this
machine, not of one repository: one screen shows every live branch of every project with Runs
on this machine and every Human review waiting for a person. It shows and changes the same state
as the `artifactize` CLI; a change made by either shows in the other.

Hovering only highlights what is under the pointer: no popup, summary, tooltip or menu opens on
hover, and information opens only on a click. A pane is never wider than its place: its width
is set by the layout or by a drag, never by what it shows, and what it shows wraps or scrolls in
its own box. The Detail's tabs show as rounded chips, the chosen one filled; a choice within a
tab, such as its Summary or its log, shows as plain text, the chosen one dark and bold and the
other light. The marks the journeys write as characters (a tool's `▶`, a star's `☆` and `★`,
`✕`, `+ Add`, a verdict's glyph) are drawn as the app's own icons, one per meaning, each
read aloud as what it means; a Tool log's lines are text and keep their characters.

A screen shows what the task at hand needs and says it once. What runs or went well is shown
as an icon, a count or a time, not as a sentence; the app speaks in sentences only for what
went wrong, why a control is disabled, a place that would otherwise be empty and a decision
that cannot be undone. Keys are named where they are looked up, in the command palette and in
Help: on a working screen only the palette button shows its key, and every other control keeps
its key without showing it.

## Window

- **J-LAUNCH**: the app opens on its one screen, the left pane beside the main area. The window is titled "Artifactize". Started with `--repo PATH` it selects that branch; with `review ID` it opens that review, and with `review` alone the newest waiting one; with `graph --repo PATH` (also the declared Human `graph` tool) it shows that branch's Current.
- **J-SETTINGS**: Ctrl+, or the Settings button opens Settings as a modal over the screen; Esc, its Close or the button again closes it, the screen beneath as it was. Settings has three tabs, Providers, Remote and Limits.
- **J-PALETTE**: Ctrl+K or the palette button, the one control of a working screen that shows its key, opens the command palette. It lists every command that can run now, each with its key: the app's (Keyboard shortcuts, Show Settings, Show or hide the Pane, Search the branches, Open a request by ID, Refresh, Quit), then those of what the main area shows, a graph's or a Human review's. Typing filters commands, Enter runs one, Esc closes it. It opens again after any use.
- **J-HELP**: `?` lists the keys of what has focus (the left pane, a graph with its Detail, a Human review, Settings) and, for a graph, what each of its marks means: each verdict's icon beside its word, on a Current what verify would do.
- **J-REFRESH**: Ctrl+R or F5 reloads the state from disk, scans the branches again and, on a Current, scans its worktree again.
- **J-QUIT**: `q` outside a field, or closing the window, quits. With Human review claims held by this window it asks first: Esc stays, `u` releases the claims and quits.
- **J-OPEN-ID**: the palette's "Open a request by ID", or Ctrl+O, opens a saved request in the main area: a waiting Human review actionable, any other request read-only.
- **J-UPDATE**: when a newer stable release of artifactize is out, the header shows `{version} available` before Settings. A click on it opens a dialog with the running and the new version and how to update the way this app was installed: the command to run, as text that can be selected and copied, or the file to download and install by hand; when the way is unknown, the release page. A link opens in the browser; Esc or Close closes the dialog. A Microsoft Store install never shows it: the Store updates the app. The app looks up the latest release on GitHub when it starts and once a day while it runs, the same lookup `artifactize doctor` reuses, and never downloads or installs anything itself.

## Left pane

- **J-PANE**: the left side is one column: a search field at the top, the branches below it, and the reviews waiting for a person at the bottom. The divider between it and the main area is shown whenever the pane is (J-PANE-TOGGLE). There is no Scope heading, no Runs list and no screen switch.
- **J-PANE-TOGGLE**: the header's Pane switch, a button right after the app's name, or Ctrl+B, or the palette's "Show or hide the Pane", hides the left pane and its divider, the main area taking the window's whole width with its view as it was, and shows them again, the pane at the width it had, its search, selection and expanded branches as they were. The switch reads as on while the pane is shown. Hidden while focus is in it, focus moves to the main area. Whatever needs the pane shows it again first: `/` (J-PANE-SEARCH) and Esc from the main area back to the pane (J-PANE-NAVIGATE). The pane is shown when the app starts. A graph, its Detail and a Human review are read and used whole with the pane hidden.
- **J-BRANCHES**: each branch reads as its project and branch, `artifactize / feat/x`, the branch in bold and the project quieter: a Git worktree that exists now with the branch it has checked out (a detached one by its folder's name), or a folder outside Git that exists now and holds its declarations. Its projects are those with Runs on this machine and the one the app was started for with `--repo` or `graph --repo`; a worktree or folder that was removed, or whose worktree Git no longer lists, is not shown, and worktrees added or removed appear or go within seconds, without a reload. Who ran a Run, an agent session or a person, makes no entry of its own: a branch's Runs are the Runs of that project on that branch, from whichever folder they ran in.
- **J-BRANCH-RUNS**: a branch is folded or expanded, any number expanded at once, with a chevron before its name. Folded, its newest Run sits under its name, a dot in its status colour, its status word and its age on the right (a running one its time so far), or `No Runs yet`. Expanded, its timeline sits there instead, newest first: one entry per Run, its status dot, status word and age and, below, one line: the comment the Run was requested with (`verify --comment`), cut short to one line, or else its Run ID, the dots joined by a line; while a Run is in progress on the branch the timeline starts with it, otherwise with the **Current**, a ring. **Older runs** at its end brings older Runs in below the oldest. A click on a branch expands it and shows its newest entry; a click on its chevron only expands or folds it; a click on an entry shows that one in the main area, the shown entry in a grey pill. The branch the app was started for starts expanded.
- **J-BRANCH-STAR**: a star at the end of a branch's name line, faint until it is on, pins it: starred branches are listed before the others, each group in the search's order, and stay starred for every later monitor of this machine's user until the star is taken away.
- **J-PANE-SEARCH**: `/` focuses the search, showing the pane first when it is hidden, and so does Ctrl+F unless a graph is shown and focus is outside the left pane (J-GRAPH-FIND); whose starting query is `sort:recent`. Free text and `key:value` terms must all match: free text matches part of a project, a branch or a waiting review's eval, `repo:` and `branch:` part of that one field, and they narrow the branches and the waiting reviews alike; `sort:recent` puts the branch with the most recent Run first and branches without Runs last, `sort:name` orders them by project and branch. Suggestions complete keys and values; Esc closes suggestions, then puts back `sort:recent`, then returns to the list.
- **J-PANE-NAVIGATE**: ↑ ↓ or `j`/`k` move through the branches, the timelines of expanded branches and then the waiting reviews, the list scrolling to show the selection; a branch shows its newest entry and a timeline entry shows itself. → expands the selected branch or enters its timeline, ← steps back out of it or folds the branch, and ↓ past a timeline's oldest entry brings older Runs first. Enter moves into the main area, and Esc there, with no Detail open, returns to the pane, showing it first when it is hidden.
- **J-WAITING**: the waiting Human reviews of every repository on this machine, those of removed branches included while their folder exists, newest at the top, each with its eval, its project and branch, how long it waits and, once claimed, who claimed it. With none waiting they are a thin bar at the bottom of the pane reading `(0)`; each waiting review adds a row and the area grows upward like a stack, up to half of the pane's height, beyond which the list scrolls. A review whose repository folder is deleted leaves the stack on its own, unless another worktree still waits on the same review, which then lists it as its own. A click or Enter on one opens the review in the main area.
- **J-LIVE**: a change made by another process (a new Run, a result, a claim, a submission, a worktree added or removed) appears in the open app without a reload.
- **J-RESIZE**: the divider between the pane and the main area can be dragged to resize them; the split stays as dragged whatever the main area shows, and comes back as dragged when a hidden pane is shown again. Dragging the Detail's left edge sets its width, between a readable column and leaving some graph visible, never over the left pane; the Detail keeps that width when opened again and in the next launch. Hovering a divider or the edge shows only the resize cursor.

## Main area

- **J-MAIN-RUN**: a Run chosen in the pane fills the main area with the graph of its Artifacts and their verdicts. The main area's header is one row: the Run's ID and, beside it, the Run's headline, its verdict and what needs attention: each eval that is RED or ERROR and each sign-off that waits, by its status's icon and its name, cut at the row's end. Right under it come the graph's tool strip and the graph. The Run's tally, how long it took, its comment in full and what it waits for are in the Run's Detail (J-DETAIL). With nothing chosen, while loading, on an error or with an empty graph the graph's place stays and says so. What went wrong, such as Runs that cannot be read, shows as a few words in the main area's header without moving or hiding the graph; a click on it shows it in full.
- **J-MAIN-CURRENT**: a branch's Current scans its worktree as it is now, as `artifactize status` does. It draws the graph of its current declarations at once, every Artifact still being checked; as soon as the scan knows what verify would do with an Artifact, its node is coloured in place, as a Run's Artifacts are, by whether it is reusable (every eval's result would be reused without evaluation), needs evaluation, waits or is blocked. A node shows the icon of what would happen with it, its name and, once it is checked, how many of its evals would be reused of how many (J-GRAPH-COLOURS; read aloud, it says which, with how many of its evals would run, or that it is still being checked). While the scan runs, the main area's header shows, beside the Current's name, the checking icon and how many Artifacts are still being checked of how many (read aloud as "Checking n of m Artifacts"); once it ends, the time it was scanned at; if it fails, why in words, the graph staying; Refresh sits at that row's end. It scans again when chosen again, on Refresh and when a Run of the branch ends, every Artifact being checked again; while a scan of the branch is still running, these show that scan instead of starting over, and after a Refresh one more scan follows once it ends, so what changed meanwhile shows.
- **J-MAIN-REVIEW**: a waiting review opened from the pane fills the main area as a Human review (J-HUMAN-LAYOUT), its eval named once, as `{Artifact}/{eval}` and its title, in the main area's header; choosing a branch or a timeline entry leaves it without closing it.

## Detail

Both graphs, a Run's and the Current, take the pointer: Tab reaches their Artifacts and Enter on one does what a click does, and Ctrl+F finds an Artifact or an eval by name, or lists the starred Artifacts (J-GRAPH-FIND), and `m` minimizes or expands a whole (J-GRAPH-MINIMIZE); they have no other keys of their own. Above each graph, right under the main area's header, sits the graph's tool strip, one row of what acts on the graph and nothing else: Find, Zoom out, the zoom in percent and Zoom in, and Fit View. The graph's keys and what its marks mean are in Help (J-HELP). Nothing but the find field floats on a graph.

- **J-DETAIL**: a click on an Artifact opens its Detail, a panel docked at the graph's right edge over the graph, from the graph's top to the main area's bottom without a gap, below the main area's header and the graph's tool strip, which stay readable and usable, never beside the left pane, the graph staying visible on its left. It opens on the Artifact's own tab, which has no chips: its list of evals leads to each eval's tab (J-DETAIL-NEIGHBOURS). On an eval's tab the Detail's tabs read as a path, `[Artifact icon] {name} / [eval] [eval] …`: the Artifact's own chip, which leads back to the Artifact's tab, the Artifact icon before its name, read aloud as "Artifact {name}"; only the name is cut short when long (the Detail's title shows it whole), then a `/`, then one chip per eval showing its verdict's glyph and colour, on a Current whether it would run, would be reused or is still being checked. Eval chips that do not fit on one line wrap onto the next, within the Detail; the `/` stays with the Artifact's chip. Close is the one control of the Detail's header besides an Artifact's star (J-DETAIL-STAR). A click on another Artifact shows that Artifact's Detail; a click on the graph's background, Close or Esc closes it, after first cancelling a Human review's running work and then leaving its form (J-HUMAN-ESC). A click on a Run's headline opens the Run's Detail: its outcome (its status and the sentence of it, the evals that failed, its tally, how long it took and its comment in full) and what it waits for. Everything in the Detail, transcript and log lines, long words and code included, stays within its width.
- **J-DETAIL-STAR**: a ☆ beside the title of an Artifact's Detail stars the Artifact, a favorite: it turns ★, and a click on it again takes the star away. A starred Artifact stays starred on every branch of its project, in Runs and Currents alike, for every later monitor of this machine's user until the star is taken away.
- **J-DETAIL-NEIGHBOURS**: the Artifact's own tab is shown first. It lists the Artifact's evals with their verdicts (a click on one shows its tab). Under Neighbours, folded until it is unfolded (J-DETAIL-SECTIONS), it draws the Artifact between its neighbours with the graph's nodes and edges, the Artifacts its evals use on its left and those whose evals use it on its right; the drawing does not pan, zoom or drag, and a click on a neighbour opens that neighbour's Detail. Then come its Human tools (J-DETAIL-TOOLS) and its path; every other fact, what it waits for included, folds under Debug. Each of these is a section under its own header row (J-DETAIL-SECTIONS).
- **J-DETAIL-SECTIONS**: below its tabs the Detail shows sections, each under a header row with its name and, while it is folded, a short summary at the row's right end that stands for what it hides: an Artifact's Evals, Neighbours, Tools, Tool log and Path, an eval's Result, Execution options, Execution metadata and Fingerprint, a Run's Outcome, Waits for, What and Provenance, and Debug, or a Run's Technical, last. A click on a header row, or Enter or Space on it focused, folds its section to that row alone, and again unfolds it. A section stays folded or unfolded as a person left it, by its name, in every Detail opened later and in the next launch. Until then what a tab is opened for is unfolded (Evals, Tools, Path, Result, Outcome, Waits for) and what is read now and then starts folded (Neighbours, a Tool log without runs, Execution options, Execution metadata, Fingerprint, What, Provenance, Debug and Technical). A Human review's Tools, Tool log and Result stand under the same rows and do not fold.
- **J-DETAIL-TOOLS**: an Artifact's chip lists the Human tools the Artifact declares, with the look and behaviour of a Human review's Tools and Tool log (J-HUMAN-TOOL, J-HUMAN-LOG): a click on a tool's `▶` runs it at once in the branch's worktree as it is now, whichever Run is shown, with no claim, and records nothing as a review's evidence. Its runs show in the Artifact's Tool log while the app runs; a run unfolds a Tool log that was folded, as it is until its first run. The graph's nodes carry no tool buttons.
- **J-DETAIL-SUMMARY**: an eval's tab shows its Summary: its status, beside it in grey what running it took and spent (time, tokens in `k` or `M`, model) or what reuse saved; its instruction; its result, each owner field by name and a list as numbered items; then Execution options, Execution metadata and Fingerprint when present, folded until unfolded (J-DETAIL-SECTIONS); every other fact, what it waits for included, folds under Debug. What the status says is not repeated below it. On a Current it shows whether the eval would run, would be reused or is still being checked and why, and the result it would reuse. An eval with a log switches below the tabs between its Summary, shown first, and its log, a plain text choice a level below the tabs: an Agent eval's Agent log (its transcript, with its own scrollbar) or a runtime eval's Runtime log (its saved output). A Human eval's tab in a Run holds its review and sign-off.
- **J-GRAPH-COLOURS**: a node says its verdict (GREEN, running or waiting for a Human, waiting, RED, ERROR, blocked), on a Current what would happen (reused, would run, waiting, blocked) or that it is still being checked, with that verdict's icon before its name and a strip along its bottom, both in the verdict's colour; its face and its outline stay neutral. After its name a node with evals says how many of them are GREEN of how many it has (`2/3`), on a Current how many would be reused; one still being checked says none. Edges are neutral, except an edge that leaves a RED, ERROR or blocked Artifact, drawn in that Artifact's colour, so what holds a blocked Artifact shows. Icons, strips, counts and edges change in place when a result arrives or a scan learns what would happen. A verdict has one colour wherever the app shows it: a node's colour is the colour the same status has in the left pane, in a chip and in a row.
- **J-GRAPH-PARTS**: on both graphs an Artifact made of parts, those its folder holds and those its `parts` names, is drawn as a box that encloses its parts' nodes, its name, its verdict's icon and a strip in its verdict's colour at the box's top; a part with parts of its own is a box inside it, as deep as the parts go. The box is the whole and the nodes in it are its parts, and each is an Artifact of its own: a click on the box outside its parts opens the whole's Detail, a click on a part opens the part's, and Tab reaches a whole before its parts. Edges to and from a whole meet its box; edges between Artifacts in different boxes are drawn and coloured like any other. The layout is made for parts that belong to one whole, each whole's parts laid out together inside it. A part of several wholes is drawn inside each of them, each copy with the part's edges; selecting one copy highlights every copy of it, and its Detail says that it is drawn in each of those wholes, naming them. The find field lists such a part once and goes to its copy in the first of its wholes.
- **J-GRAPH-MINIMIZE**: a whole's box has a Minimize button at its top right, which Tab reaches after the whole and before its parts. `m` does what that button does for the whole focused on the graph, or whose button is focused, else for the whole whose Detail is open, while focus is outside the left pane; focus stays where it was. Typed in a field, or during an input method's composition (J-HUMAN-TEXT), `m` does nothing. The button's tooltip and Help name the key. It draws the whole as a node of a node's size: its name, its verdict's icon and colour, how many parts it has and an Expand button that draws its box again. The edges to and from the Artifacts a minimized whole hides meet it instead, those between the same two drawn once in the light that comes first, as an Artifact's light comes from its evals'; edges among them are not drawn. A minimized whole is otherwise a node: a click on it outside its button or Enter on it opens its Detail, Tab reaches it and then its Expand button, and it is highlighted while an Artifact it hides is open. The find field lists what it hides as before and goes to the minimized whole for it. A whole stays minimized on every graph of its branch, its Runs' and its Current, until it is expanded or the app quits; a part of several wholes stays drawn inside those not minimized.
- **J-GRAPH-LARGE**: a graph too large to draw at once stays navigable: panning or zooming the camera draws the Artifacts it brings into view. Zoomed out so far that names would be too small to read, each Artifact is drawn as a block of its verdict's colour and a whole as its box's outline in its colour, and a click on one still opens its Detail; zoomed in until names read, each is a node again (J-GRAPH-COLOURS).
- **J-GRAPH-NAVIGATOR**: whenever part of a graph lies outside the view, whatever the graph's size, a Navigator shows at the graph's bottom right, left of the Detail when one is open: the whole graph in small, each Artifact a block of its verdict's colour, with the part in view framed. A click or a drag in it moves the camera so that place is in the middle of the view, the zoom kept. It goes when the whole graph is in view again. Hovering it opens nothing.
- **J-GRAPH-FIND**: the graph's tool strip has a Find button; Ctrl+F does the same. With a Run's graph or a Current shown, a click on that button, or Ctrl+F with focus outside the left pane, on the graph or in the Detail, opens a find field over the graph's top left. With nothing typed it lists the graph's starred Artifacts (J-DETAIL-STAR) as if they had been found, in the graph's order, each with its verdict's glyph and colour; when none of the graph's Artifacts is starred, it says how to star one. Typing lists the Artifacts and evals whose names contain the text, ignoring case, in the graph's order: an Artifact by its whole name, an eval as `{Artifact} / {eval}`, each with its verdict's glyph and colour (on a Current, what would happen); the first 50, then how many more match, or that none does. ↑ and ↓ choose one; Enter or a click opens it, an Artifact's Detail on its Artifact tab and an eval's on that eval's tab, closes the field and moves the camera so the Artifact sits in the middle of the graph left of the Detail, zooming in only as far as its name needs to be readable. Esc or a click outside the field closes it, the graph and the Detail as they were.
- **J-GRAPH-CAMERA**: a graph shows whole when it first appears, never enlarged beyond its nodes' own size: a small graph sits at that size in the middle of the graph's place. From then on only the person moves its camera, by panning, zooming (the wheel, or the tool strip's Zoom out and Zoom in, the zoom in percent between them), Fit View (whole again, with the same limit), the Navigator (J-GRAPH-NAVIGATOR), opening what the find field found (J-GRAPH-FIND) or minimizing or expanding a whole (J-GRAPH-MINIMIZE), which keeps that whole's top left corner where it was on the screen: opening, switching, resizing or closing the Detail, a result or scan arriving and a new layout never zoom or pan it.

## Human review

- **J-HUMAN-CLAIM**: `c` claims a waiting Human review for this reviewer; `u` releases it. A claim made elsewhere shows as taken, the claimant named beside its stage.
- **J-HUMAN-LAYOUT**: a Human review has one order: its instruction, the Tools, their Tool log and the Result. Its eval's title is said once, above it (the main area's header, or the Detail's title), and the review opens with its stage alone: CLAIM, or REVIEW (yours) once claimed here. The request's ID, its mode, its claimant and how long it has waited fold under Debug at its end. On a Human eval's tab in the Detail, and in a main area less than twice as wide as the Detail, it reads top to bottom in one column no wider than a readable measure. In a main area at least twice as wide as the Detail, the Tool log is the large view on the left, from under the main area's header to its bottom, and the instruction, the Tools and the Result are a column at the right, where the Detail docks and of the Detail's width. Either way Release and Submit sit in one row right under the Result, in the Result's column, and between them what running work has to say: its seconds and Cancel, or its failure. What ended well is said by the Tool log's end line or by the completed result alone.
- **J-HUMAN-TOOL**: the Tools are grouped by the Artifact that declares them, the reviewed one first, a group named by its Artifact only when more than one declares tools, each a `▶` button; after a claim a click on it runs it at once. A launch tool opens its application and returns at once; a failing tool shows its error.
- **J-HUMAN-LOG**: every run of the review shows in the Tool log as it happens: `▶ HH:MM:SS · operation · Artifact`, then each line the tool prints, stderr in red, then its end line (`■ exit 0`, `■ launched`, `■ done`, `■ error: …`). A launched application's lines keep arriving under its own run until it exits. The log is monospace, wraps, scrolls on its own and follows its newest line unless the reader scrolled up; its text can be selected and copied into the result. A submission clears it.
- **J-HUMAN-GREEN**: after a claim `g` opens the GREEN form built from the eval's pass schema; Ctrl+S submits. The completed result stays open.
- **J-HUMAN-RED**: `r` opens the RED form; a result that fails its schema is not submitted, the failing path is shown and the form stays correctable. Ctrl+G and Ctrl+R switch the verdict while editing.
- **J-HUMAN-FORM**: the form shows text, number, true/false and choice fields, a list of text with `+ Add` and `✕` per item, and repeated groups of fields with `+ Add` for a group and `✕` per group, one group always left to type in. Constants are filled in and not shown; `*` marks a required field and an empty optional one says Optional in grey. There is no JSON editor.
- **J-HUMAN-TEXT**: text fields take any language, including Korean composed by an input method; no key typed during a composition triggers a shortcut.
- **J-HUMAN-ESC**: Esc cancels running work, then leaves the form, then leaves the Detail or, for a review opened from the pane, returns to the pane, showing it first when it is hidden.

## Settings

- **J-SET-PROVIDERS**: the Providers tab lists the built-in providers vertically on the left (Codex, Claude Agent, OpenAI, Anthropic, Gemini), then the custom providers by name, then **+ Custom provider** at the bottom. Choosing one shows its setup on the right.
- **J-SET-CODEX**: Codex signs in to or out of the ChatGPT account through the browser; a sign-in in progress can be cancelled, and when the browser cannot return, **Finish by hand** unfolds the sign-in's address and a field where the redirect URL can be pasted.
- **J-SET-CLAUDE-AGENT**: Claude Agent shows Claude Code's sign-in as Claude Code itself reports it: `claude` not found, not signed in, signed in with its login method and plan, or the error it failed with; Check again asks again. It signs in and out by running the user's own `claude auth login` and `claude auth logout`: Claude Code opens the browser and keeps its own login, which artifactize never reads, copies or stores. While it signs in, the sign-in can be cancelled, and **Finish by hand** unfolds the URL Claude Code prints and a field where the code its page gives can be pasted; the status updates when it ends.
- **J-SET-KEY**: OpenAI, Anthropic and Gemini each show whether their key is set, from the environment (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY`) or saved here, never its value. A key can be pasted and saved, or removed; a set environment variable is used first.
- **J-SET-CUSTOM**: **+ Custom provider** adds a provider with a name: an alias of a built-in provider, used with its sign-in or key, or an endpoint with its API (OpenAI Responses, OpenAI Chat Completions, Anthropic Messages or Gemini), base URL and optional key. Any number can be added; a custom provider can be changed or removed. An eval uses it by its name in `backend`.
- **J-SET-MODELS**: a provider's setup lists the models it offers, each by its name with its ID beside it.
- **J-SET-REMOTE**: the Remote tab signs in to a shared review store with its URL, share level and token, shows its status in one line (signed in or out, the reviewer and what was pushed today, or the error), pushes results (or a dry run), and signs out.
- **J-SET-SIGNOFF-GRACE**: the Limits tab shows, in the seconds field that changes it, how long a Run with only sign-offs left, and none of them claimed, waits before it ends (120 seconds unless changed), and changes it for the Runs started afterwards.
