Detail: the inspector of the selected Artifact

A click on a node opens its Detail: a panel docked at the graph's right edge, meeting the graph at a line, with the graph still visible on its left. The selection drives it: the outlined node and the Detail's title name the same Artifact. The Artifact's tab lists its evals, and a click on one opens that eval's tab, where chips read as a path back; the first figure shows the Artifact's tab, the second an eval's Summary. On a Current the Artifact's tab also reads its definition: the last figure shows its Definition and its Source, the macro call that binds it as authored, a click away from what it expands to.

  1. 1
    SelectionThe opened node keeps its face, its outline and its strip, ringed by a 1px current mark 2px outside it, clear of the strip. It is the Artifact the Detail is titled with.
  2. 2
    Dock headerThe title (the whole name, wrapping), the star beside it, Close. The Detail starts under the stage header, whose tools stay in reach. The outlined node and this title are the two places that name the Artifact.
  3. 4
    NeighboursFolded until asked for: the graph beside the Detail already shows them. Unfolded, it draws the Artifact between its neighbours with the graph's nodes and edges: the Artifacts its evals use on its left, those whose evals use it on its right; a click on a neighbour opens it.
  4. 5
    Eval rowsThe tab's navigation: a click on a row opens that eval's tab. Dense rows of four columns: the verdict's icon, the name, the status words in the status colour, and time and tokens pinned to the panel's right edge in secondary ink with tabular figures.
  5. 6
    SectionsEach a header row: the fold icon and the section's name in ink, nothing else; a click folds it to that row, and what it holds shows once it is unfolded. A section with nothing to show is not shown: the Tool log joins them with the first run of a tool.
  6. 20
    Navigator beside the DetailPart of the graph (here docs and site, and part of cli) lies behind the Detail, outside the view, so the Navigator shows at the bottom right of the graph's visible part, left of the Detail's edge, never over it; it goes once the whole graph is in view.
  1. 21
    Drawn inOnly for a part of several wholes: a fact under Debug naming every one of those wholes, in graph order, also while a minimized whole hides one of its copies and only one copy is drawn; every drawn copy of it carries the selection's outline. A part of one whole, or of none, has no such fact.
  2. 22
    PathOn a Run, read-only facts in secondary ink, selectable: Target, what the Artifact's PATH names, as its PATH writes it, in monospace (for a folder, a file, an aspect or a graph, its path in the worktree; here a Live Artifact, the address outside the worktree that its PATH names), and, for a Live Artifact only, Address, below it, the address it is observed at, in monospace. Nothing here edits it.
  1. 25
    A tool runningA click on a tool's run icon runs it at once in the branch's worktree, whichever Run is shown, with no claim. While it runs, every tool button of the Artifact is disabled, and a line under the tools shows the running icon and Cancel, which stops it; a tool that fails to run says so in red on that line. A launch tool returns at once.
  2. 26
    The Artifact's Tool logA section of its own under Tools, shown from the first run on and unfolded by every run, even when it was folded: each run one line as a review's runs are, the running one unfolded into its start line, then each line as it prints; an output tool's end line (■ exit 0, or red for a failure) closes its run once it ends. A launch or viewer tool returns at once: its end line is ■ launched, once the file is handed to its application or the Artifact Viewer opens, and a launched application's lines keep arriving under that same run until it exits. Nothing in it is a review's evidence.
  1. 3
    Chip pathThe title keeps the Artifact's star on every tab: here cli is starred, so the star is filled (the first figure shows it outlined, not starred). Only on an eval's tab: the Artifact's chip, which leads back to its tab, and a /, the two one group that never breaks, only the Artifact's name cut when long; then one chip per eval: rounded chips of 22px, the chosen one bright over a thin current mark; eval chips lead with the verdict's icon in its colour; many chips wrap.
  2. 7
    View switchOnly for an eval with a log: plain text a level below the chips, Summary, chosen first, then the log, Agent log (its transcript) for an Agent eval or Runtime log (its saved output) for a runtime eval, as here. The chosen view is in the strong text colour over a thin current mark, the other in the quieter one, both at one weight; both read plainly on the panel. No chip, no fill. An eval without a log has no switch, its Summary standing alone.
  3. 8
    Status lineThe verdict's icon and word in the status colour, at the line's weight; beside it in neutral secondary ink what running it took and spent (time, tokens in k or M, and the model for an Agent eval) or what reuse saved, and how it ended, said here once.
  4. 9
    Header → label → valueThree levels: a section's header row, then its facts as a key/value grid, keys right-aligned in secondary ink, values in tabular figures. A Result is its issues, numbered: a runtime eval's one issue led by its exit code, its reason the end of what the command printed, and an Agent eval's each led by its priority. The Result is unfolded; the sections read now and then are folded to their names, and their values show once unfolded.
  1. 10
    Run DetailThe same dock, titled with the Run's ID; it has no chip path, since a Run has no evals of its own to tab through. It holds what the Pane's entry leaves out: what failed and what waits, the tally with its words, the duration and the comment in full.
  2. 11
    SectionsOutcome and Waits for (what the Run waits for, then its pending evals) are unfolded, their facts as key/value grids; What, Provenance and, last, Technical are folded to their names.
  1. 27
    A Human eval's stageA Human eval that waits says so in its row's status words, its stage right beside them in secondary ink: · claimable, · yours once this reviewer holds it, · taken by {claimant} while another reviewer holds it; its actions sit in one row under it.
  2. 28
    The review's actionsUnder the row, indented to its name: Claim to review while it can be claimed, or Release claim while it is yours, as a small button; then Open in Review, a reference in secondary ink led by the open icon, which shows the review in Review. A review taken by another reviewer offers Open in Review alone.
  1. 12
    A Current's chipsEach eval chip leads with what verify would do with that eval, as its icon in the plan's colour: would be reused, would run, or still being checked. Waiting and blocked mark Artifacts' nodes, not evals.
  2. 13
    A Current's SummaryThe plan line replaces the verdict line: what would happen and why, in the plan's colour and secondary ink; then the result it would reuse, when there is one; then Execution options, Execution metadata and Fingerprint, folded, each only when its facts are present, and Debug. An eval whose reused result has a log gets the Summary / log switch as on a Run; tests here would run, so it has none.
  1. 14
    DefinitionUnfolded, in place of a Run's Path: where the Artifact is bound, its file and line; the macro it calls, for an Artifact made by one; its Path; its Parts, when it has any, each a link to that part's Detail; and the toolsets it composes. A key/value grid of read values, no field among them.
  2. 15
    Bound and MacroThe file and line of the artf statement that binds it, selectable, and the macro it calls. A target that is missing is said in red beside its Path.
  3. 17
    SourceThe code that binds the Artifact, in monospace, each line numbered as in its file, folded until unfolded. It is read, never written here: what changes it is an edit of the file, in Chat or elsewhere.
  4. 18
    Authored and ExpandedOnly for an Artifact made by a macro: plain text a level below the section's row, as an eval's view switch is. Authored, chosen first, is the call as written; Expanded is the declaration it expands to, its parameters, defaults and spreads filled in.

Rules

D-INS-1
The Detail is the inspector: a panel docked at the Main area's right edge over the graph's canvas, from the canvas's top to the area's bottom, below the stage header (D-MAIN-1), whose tools stay readable and usable, with no gap at its top, right or bottom, never beside the Pane. It is a --surface-panel panel meeting the graph at lines, --line-panel at its left and the stage header's --line-panel at its top, with square corners and no shadow; its left edge takes a drag, hovering it showing the resize cursor alone (D-SYS-7), and the drag stops at the limits: never narrower than a readable column of 320px, never so wide that less than 240px of graph shows on its left, and never over the Pane; the width a drag leaves is kept, and the Detail opens at it again, after closing and after the next launch alike. a floating card (a gap, a radius or a shadow around the Detail); the Detail pushing the graph aside or moving its camera.
D-INS-2
The Detail's header is a panel header row, 32px as the stage header is (D-MAIN-1): the title at --text-small semibold, wrapping to show a long name whole, naming what the tab shows with the Artifact's name whole in it (Artifact {name} on the Artifact's tab, {Artifact}/{eval} · {eval title} on every eval's tab, a Human eval's included, the Run's ID on a Run's), the star beside it on every tab of an Artifact, its own and each eval's (the star icon in --ink-3 until the Artifact is starred, then the filled star in --ink; a click puts the star on or takes it away, for that Artifact on every branch of its project, in Runs and Currents alike, and for every later monitor of this machine's user), Close at the end. What closes the Detail, and what goes first, is J-DETAIL and J-HUMAN-ESC: whatever else it holds, an Artifact's tool still running included, it closes; an open find field (D-OVL-4) takes an outside click first, the Detail staying open. With focus in the Detail, its 2px --accent top line shows. On the Artifact's own tab, the outlined node and this title are the two places that name the opened Artifact (D-INS-6); an eval's tab also names it in its Artifact chip (D-INS-3). a cut title; a second close control; a key cap on Close.
D-INS-3
The chip row shows only on an eval's tab, under the header, closed below by --line-group; the Artifact's own tab has none, since its Evals rows lead to every eval (D-INS-4). It reads as a path: the Artifact's chip (the Artifact mark and its name, only the name cut), which leads back to the Artifact's tab, a /, then one chip per eval. Chips are of --row-dense height, --radius-chip, --text-small, with a 1px --line-group border and --ink-2 text; the chosen chip has its words in --ink over a 2px --current-mark line along its bottom, unfilled and at the others' weight (D-SYS-13); each eval chip leads with its verdict's icon in the status colour (on a Current, with what verify would do, D-INS-8); the / stays with the Artifact's chip and the rest wrap. pills in the accent; a chip without its icon; a chip row above the Artifact's own list of evals.
D-INS-4
The Artifact's tab is sections, top to bottom, each under its header row (D-INS-9): Evals (the eval rows, each of which opens that eval's tab), Neighbours (folded until asked for; unfolded, the drawing, at least 72px, with a camera that does not move: the graph's nodes and edges, the Artifacts its evals use on the left, those whose evals use it on the right), Tools (its Human tools, each a small button with the run icon and its description, as a review's, D-REV-2: a click runs the tool at once in the branch's worktree with no claim; while one runs, every tool button of the Artifact is disabled, and one line under the tools shows the running icon in --running and Cancel, which stops the run; a failure to run takes that line in --red; a launch tool returns once its file is handed to its application), Tool log (only once a tool has run: an Artifact without runs has no Tool log section; it shows each run as a review's runs are, one line each that unfolds its lines, D-REV-3, the running one unfolded with no end line yet, a launch tool's run ended by its ■ launched line, under which the application's lines keep arriving until it exits, and every run unfolds the section when it was folded), Path (on a Run, read-only facts of a key/value grid in --ink-2, selectable, without a field: Target, what the PATH names as it writes it, in --mono: the path for a folder, a file, an aspect or a graph, and for a Live Artifact the address outside the worktree that its PATH names; and, for a Live Artifact, Address, the address it is observed at in --mono, added below Target; on a Current, Definition and Source in its place, D-INS-10, D-INS-11), then Debug, folded: unfolded as any section is, by a click on its row (D-INS-9), it holds every other fact of the Artifact as a key/value grid, keys right-aligned in --ink-2, values selectable and in --mono for IDs, paths and hashes, what it waits for first (the Artifacts or evals it waits on, when there are any), then the rest its Run or its scan holds of it. For a part of several wholes, on both graphs, Debug holds Drawn in, every whole whose parts name it, in graph order, also when a minimized whole hides a copy so that fewer copies are drawn; an Artifact that is a part of one whole, or of none, has no such fact. An eval row is --row-dense in four columns: the verdict's icon in the status colour, the name, the status words in the status colour, and the last column (time, tokens) pinned to the panel's right edge in --ink-2 tabular; on a Current the words say would run, would be reused or checking. accent-coloured section headings; times trailing the status words instead of aligning at the right; a section, a sentence or an empty box for a Tool log without runs; the Artifact's name or its tally repeated in the tab's body; a tool button on the graph's nodes; a shared part whose tab names only the whole of the copy that was clicked; a field or an edit control in a Run's Path.
D-INS-5
An eval's tab: for an eval with a log, the view switch as plain text under the chips, Summary then the log (Agent log, the transcript, for an Agent eval; Runtime log, the saved output, for a runtime eval), Summary chosen when the tab opens; the chosen view in the strong text colour, --ink, over a 2px --current-mark line, and the other in the quieter one, --ink-2, both at weight 400 (D-SYS-13), both readable on the panel; no radius, no fill; an eval without a log has no switch; then the status line (the verdict's icon and word in the status colour, at weight 400; beside it in --ink-2 what running it took and spent, the time, the tokens in k or M and the model when there was one, or, for a reused result, what reuse saved, and how it ended; the line wraps rather than drop any of them), the instruction, then Result, unfolded: each field the eval's owner set in its schema, by its name as a key/value grid (keys right-aligned in --ink-2), a list's value as numbered items; then Execution options, Execution metadata and Fingerprint, each folded to its name (D-INS-9), their facts, once unfolded, in a key/value grid with keys right-aligned in --ink-2 and values in tabular figures; Debug folded last: unfolded as any section is, by a click on its row (D-INS-9), it holds every other fact of the eval as the same key/value grid, values selectable and in --mono: its request (the request ID), its source (the definition file and the eval's name), what it waits for, and the rest of its record; then its raw result whole, as --mono text at --text-small on --surface-input with a --line-input border, wrapping and scrolling in its own box. What the status line says (the duration, the exit) is not said again below it. A log replaces the body below the switch in --mono at --text-small, wrapping and scrolling in its own box. a JSON dump as the Summary; costs in the status colour; the exit code or the duration repeated in the Result or the metadata; a switch with a single view; a log chosen first.
D-INS-7
The stage header's Run details opens the Run's Detail in the same dock (D-INS-1, D-INS-2), and closes it again, its word --ink-bright while it is open (D-MAIN-1); the Detail is titled with the Run's ID and has no chip row. It holds what the Pane's entry leaves out. Outcome, unfolded: the status, its icon and word said once, the evals that failed by name, the tally (each status's icon in its colour, its count and its word), what the Run took, and its comment in full. Waits for, unfolded: what the Run waits for, then its pending evals in --ink-2. Then What, Provenance and, last, Technical, folded to their names; Provenance says what started the Run: the CLI, an MCP client, or a Chat session by its title, as a fact in plain text; the way back to that session is the stage header's way back alone (D-MAIN-4). Facts are key/value grids (keys right-aligned in --ink-2, values in tabular figures), and every section folds and unfolds by its header row (D-INS-9). tabs on a Run's Detail; the Run's graph redrawn inside it; a sentence that says the status again (NOT SATISFIED at Run end beside RED).
D-INS-12
On a Run's graph, an Artifact's tab offers each Human eval's review where its row is: the row's status words say waiting Human in --human, its stage right beside them, in the row, in --ink-2 at --text-small: · claimable, · yours in --ink while this reviewer holds the claim, or · taken by {claimant}; under the row, indented to the eval's name, one row of --control holds its actions: Claim to review (while it can be claimed) or Release claim (while it is yours) as a small quiet button, then Open in Review, a text reference in --ink-2 led by the open icon (D-REF-1). A claim in progress or its failure shows in that row as the review's actions row does (D-REV-5). A review taken by another reviewer offers Open in Review alone; a submitted one offers neither, its row saying its verdict. The Human eval's tab, which holds the review itself (D-REV-1), shows Open in Review in its head line after the claim's state (D-REV-11). the claim actions as a menu or on hover; Open in Review as a primary button; the stage repeated as a pill in the row; Claim to review offered on a review taken by another reviewer.
D-INS-8
Over a Current the Detail keeps its anatomy and changes what the marks say: each eval chip leads its eval's name with what verify would do with that eval, one of three: would run, would be reused, or still being checked, as that plan's icon alone, in its one colour, with no words on the chip; each eval row leads with the same icon and says the same plan in words in that colour, as the Summary's plan line does (would run --running, would be reused --reused, checking --checking, the colours of the nodes' same plans). Waiting and blocked are marks of an Artifact's node, not of its evals: an eval of a waiting or blocked Artifact still says whether it would run or be reused; an eval's tab shows, in place of the verdict line, the plan (what would happen, in its colour at weight 400) with its reason beside it in --ink-2, then the instruction, the result it would reuse as a Result section under its header row when there is one, laid out as a Run's (each owner field by name, a list as numbered items, D-INS-5) (the plan line already says why an eval would run), then Execution options, Execution metadata and Fingerprint, each a section folded to its name when its facts are present, and Debug, folded, last; when the eval has a log (the Agent log or Runtime log of the result it would reuse), the view switch of D-INS-5 stands under the chips as on a Run, Summary first; an eval without one, such as one that would run or is still being checked, has no switch; and a Current has no Human review. A node still being checked recolours its chips and rows in place as the scan learns. a Run's verdict words on a Current; a log switch that has nothing to show; a waiting or blocked mark on an eval's chip, row or Summary.
D-INS-9
The inspector reads in three levels: a section's header row, a fact's label, its value. A section's header row is --row high, opened above by --line-group: the fold icon in --ink-2 (the unfold icon while the section is unfolded), the section's name at --text-small semibold in --ink, in sentence case without letter-spacing, and nothing else: no count, value or list of what it holds stands at the row's end, folded or unfolded; what a section holds shows when it is unfolded. The whole row takes the click that folds or unfolds its section, and keyboard focus as a control (D-SYS-7); folded, a section is its row alone. A section starts unfolded when it is what its tab is opened for (an Artifact's Evals, Tools, Path and Definition, an eval's Result, a Run's Outcome and Waits for) and folded when it is read now and then (Neighbours, Source, Execution options, Execution metadata, Fingerprint, What, Provenance, Debug and a Run's Technical). Once a person folds or unfolds a section, that state is kept by the section's name, not per Artifact: every Detail opened later, of any Artifact, eval or Run, shows that section so, and so does the next launch. A section with nothing to show is not shown, header row included, and no line stands in for it: an Artifact's Evals when it has no eval, its Neighbours when its evals use no Artifact, no Artifact's evals use it and it is drawn once, its Tools when the toolsets it composes have no Human tool, its Tool log before its first run, an eval's Result when it has none (on a Current, no result to reuse), its Execution options, Execution metadata and Fingerprint when it has none, a Run's Waits for when it waits for nothing, and a Debug, What, Provenance or Technical without facts. The ordinary sections of Settings stand under the same row without the fold icon: they do not fold; a Human review has no section rows, its runs folding by their own lines (D-REV-1, D-REV-3). One row is an exception, with the fold icon and taking the click: Settings' Finish by hand, a disclosure row that unfolds a sign-in's address and paste field (D-SET-5). 11px uppercase labels as section headings; a header row, or a line saying so, for a section with nothing to show; a summary, a count or a table of contents at a row's end; a box around a section; a fold control apart from the row.
D-INS-6
Selection and inspector agree: the node ringed by the --current-mark line (D-NODE-2), every copy of a shared part included (its tab naming each whole those copies are drawn in, D-INS-4), is the Artifact the Detail is titled with, or, when that Artifact is hidden inside a minimized whole, the minimized whole that hides it while the Detail still names the Artifact; opening a neighbour or another node moves both; closing the Detail removes the outline. The Find field's choice opens the Detail and moves only the camera. a Detail left open for a node no longer highlighted.
D-INS-10
On a Current the Artifact's tab has Definition where a Run's has Path, a section of D-INS-9, its facts a key/value grid of read values: Bound, the file and line of the artf statement that binds the Artifact, in --mono --ink-2, selectable; Macro, the macro it calls with its !, only for an Artifact made by one; Path, the target as the code resolves it in --mono, a missing target said beside it in --red; Parts, only when it has some, one --row-dense row per part whose name opens that part's Detail as a neighbour does; Tools, the toolsets it composes as the code writes them (files & html). Nothing in the Definition is a field or a button: the Definition reads the code, and every change to it is an edit of its file. a field, an input look, a Save, Rename, Delete or Comment control in the Definition; a Definition section on a Run; the Artifact's name repeated as a fact; a resolved Run fact (an address) shown as if written.
D-INS-11
Source follows Definition, folded until unfolded: the code that binds the Artifact in --mono at --text-small on --surface-input with a 1px --line-input border, read-only, each line numbered in --ink-2 as in its file, quieter than the code and readable; it scrolls sideways in its own box rather than wrap, so each number stays with its line, and its text can be selected and copied. For an Artifact made by a macro, the view switch of an eval's tab (D-INS-3) stands above it, Authored, chosen first, then Expanded: Authored shows the call as written, Expanded the declaration it expands to, every parameter, default, spread and @{param …} filled in and its composed tools resolved, numbered from 1 as generated text. An Artifact written out has no switch. a caret, an editable look or Save and Revert; syntax colours taken from the status palette; a switch for an Artifact that no macro makes; Expanded opened first; a separate editor window.
