# 데스크톱 {#desktop}

앱을 열면 이 머신에 Run이 기록된 모든 프로젝트의 현재 브랜치와 사람의 승인이 필요한 모든 Human
리뷰가 한 화면에 나옵니다. Run을 살펴보고, 각 브랜치가 지금 무엇을 실행할지 보고, 증거를
확인하고, Human 승인을 처리하세요. 앱은 CLI, TUI와 같은 상태를 쓰므로 한쪽에서 한 변경이
다른 쪽에도 보입니다. 모든 릴리스가 명령과 함께 앱을 제공하며, 설치 방법은 [데스크톱 앱](../getting-started/install.md#desktop-app)을 보세요.

첫 실행 때의 명령 설정, PATH 세부 사항, 업데이트, 정리는
[설치 안내](../getting-started/install.md#desktop-app)를 보세요.

## 앱 열기 {#open-the-app}

```sh
artifactize-desktop
artifactize-desktop monitor --repo PATH
artifactize-desktop review [REQUEST_ID]
artifactize-desktop graph --repo PATH
```

인자가 없으면 현재 디렉터리와 상관없이 아무것도 고르지 않은 채 앱이 열립니다.
`--repo PATH`는 그 폴더의 브랜치를 고르고 펼친 뒤 가장 새 항목을 보여 줍니다. 기본값인 `--all`은
아무것도 고르지 않으며, 어느 쪽이든 모든 브랜치가 나열됩니다. `review`는
가장 최근에 승인 대기가 된 Human 리뷰를, `review REQUEST_ID`는 지정한 요청을 엽니다. `graph`에는
`--repo`가 필요하며 그 브랜치의 [Current](#current)를 보여 줍니다. `--state-dir PATH`는
상태 디렉터리를 고르며, 그렇지 않으면 앱은 공유 상태 홈을 씁니다. `--reviewer NAME`은
협업할 때 리뷰를 맡은 사람으로 보일 이름(보통은 사용자 이름)을 정합니다. `-h`, `--help`, `help`(모드 뒤에 써도 됨)는 잘못된 인자와
마찬가지로 stderr에 도움말을 출력하고 2로 종료합니다. 앱은 종료하면 0으로, 시작하지 못하면
1로 끝납니다.

아래 단축키 라벨은 Ctrl을 씁니다. macOS에서는 기본 보조 키인 Command를 대신 씁니다.
Ctrl+K, F1, 또는 **Commands** 버튼은 검색할 수 있는 명령 팔레트를 엽니다. Enter는
명령을 실행하고 Esc는 팔레트를 닫습니다. Ctrl+, 또는 **Settings** 버튼은
Main area에 [Settings](#settings)를 보여 줍니다. Ctrl+O는 ID로 요청을 엽니다. `?`는
초점이 있는 곳의 키를 나열합니다. Ctrl+R 또는 F5는 디스크에서 상태를 다시 읽고, 브랜치를
다시 스캔하며, Current에서는 그 워크트리를 다시 스캔합니다. 키보드 초점이
Human 리뷰에 있고 진행 중인 작업이 없으면, 양식이 열려 있든 아니든 Ctrl+R이 대신 RED 명령이 됩니다.
요청을 맡았으면 RED를 열거나 RED로 바꾸고, 그렇지 않으면 먼저 리뷰를 맡아야 한다고
알려 줍니다. 그때는 F5나 팔레트의 **Refresh**가 상태를 다시 읽습니다.
앱은 시스템의 라이트 모드 또는 다크 모드 설정을 따릅니다.

마우스를 올리면 강조만 하고, 정보는 클릭하면 열립니다.

## Pane {#pane}

앱 창은 한 화면으로, 왼쪽의 **Pane**과 그 옆의 **Main area**로 이루어집니다.
Pane은 열 하나입니다. 맨 위에 검색 칸, 그 아래에 브랜치, 그리고
맨 아래에 사람의 승인이 필요한 리뷰가 있습니다. Pane과
Main area 사이의 구분선을 끌어 크기를 바꾸세요. Main area에 무엇이 표시되든 직접 조절한 비율이 그대로 유지됩니다.

### 브랜치 {#branches}

브랜치는 Git 저장소에서 작업 이력을 따로 이어 가는 단위입니다. 워크트리는 한
브랜치가 체크아웃된 폴더입니다. 한 저장소에 워크트리를 여러 개 둘 수 있으며, 각 워크트리는 브랜치를 체크아웃하거나, 브랜치 없이 커밋을 체크아웃한 분리(detached) 상태일 수 있습니다. 각 항목은 `artifactize / feat/x`처럼
프로젝트와 브랜치로 표시됩니다. 각 항목에는 현재 워크트리와 체크아웃한 브랜치를 표시하고, 분리 상태이면 브랜치 대신 폴더 이름을 표시합니다. Git 밖에서 선언한 프로젝트는 그 폴더로 표시합니다.
그 프로젝트는 이 머신에 Run이 있는 프로젝트, 그리고 앱을
`--repo`나 `graph --repo`로 시작한 프로젝트이며, 후자는 첫 Run 전에도 나열됩니다. 제거된
워크트리나 폴더, 또는 Git이 더 이상 나열하지 않는 워크트리는 보이지 않습니다. 추가되거나 제거된 워크트리는
다시 읽지 않아도 몇 초 안에 나타나거나 사라집니다. Run을 실행한 쪽이 에이전트 세션이든 사람이든
따로 항목이 생기지는 않습니다. 각 브랜치에는 어느 폴더에서 실행했는지와 상관없이 그 프로젝트의 그 브랜치에서 실행한 Run이 나옵니다.

접힌 브랜치는 이름 아래에 가장 새 Run을 보여 줍니다. 상태 색의 점,
상태, 그리고 얼마나 전에 실행되었는지(실행 중이면 지금까지 걸린 시간)입니다. 브랜치를 클릭하면
펼치고 가장 새 항목을 보여 줍니다. 이름 앞의 꺾쇠를 클릭하면 Main area는 바뀌지 않고
그 항목만 펼쳐지거나 접힙니다. 펼치면 타임라인이 Run을 최신순으로 나열하며, 각각
상태, 경과 시간, Run ID가 붙습니다. Run이 진행 중이면 그 Run이 맨 앞에 오고, 그렇지 않으면
워크트리의 지금 상태인 **Current**가 맨 앞에 옵니다. 끝의 **Older runs**는
더 오래된 Run을 가져옵니다. 항목을 클릭하면 회색의 둥근 배지로 표시되며 Main area에 나옵니다. 브랜치는
몇 개든 펼칠 수 있으며, 앱을 시작할 때 지정한 브랜치는 펼친 채로 시작합니다.

브랜치 이름 끝의 ☆로 별표를 붙입니다. 별표 붙은 브랜치가 먼저 나열되며,
각 묶음은 검색 순서를 따르고, 다음에 앱을 열어도 별표가 남습니다.
★를 다시 클릭하면 별표를 뗍니다.

↑/↓ 또는 `j`/`k`는 브랜치, 펼친 브랜치의 타임라인, 그리고
대기 중인 리뷰 사이를 이동하며, 각 브랜치의 가장 새 항목이나 도달한 항목을 보여 줍니다. →는
선택한 브랜치를 펼치거나 그 타임라인으로 들어가고, ←는 다시 빠져나오거나 접습니다. 타임라인의
가장 오래된 항목에서 ↓를 누르면 더 오래된 Run을 가져옵니다. Enter는 Main area로 이동하고,
그곳에서 Detail이 열려 있지 않을 때 Esc를 누르면 Pane으로 돌아갑니다.

### 검색 {#search}

`/` 또는 Ctrl+F는 검색에 초점을 맞추며, 시작 검색어는 `sort:recent`입니다. 일반 검색어와
`key:value` 조건을 모두 만족하는 브랜치와 대기 중인 리뷰만
표시합니다. 일반 검색어는 대소문자를 구분하지 않으며, 프로젝트, 브랜치, 대기 중인 리뷰의 eval 이름에 그 검색어가 들어 있는 항목을 찾습니다. `repo:`와 `branch:`는 각각 저장소와 브랜치 필드에 그 검색어가 들어 있는 항목을 찾습니다.
`sort:recent`는 가장 최근 Run이 있는 브랜치를 맨 앞에, Run이 없는 브랜치를
맨 뒤에 두고, `sort:name`은 프로젝트와 브랜치 순으로 정렬합니다. 자동 완성으로 검색 키와
값을 채울 수 있습니다. ↑/↓로 후보를 고른 뒤 Tab이나 Enter를 누르거나 후보를 클릭하면
검색어에 들어갑니다. 자동 완성 후보가 떠 있지 않을 때 Enter를 누르면 목록으로 돌아갑니다. 알 수 없는 키 등으로 검색어를 해석할 수 없으면 브랜치 목록 대신 오류를 보여 주고, 검색어를 고칠 때까지 두 목록을 비워 둡니다. Esc는 제안을 닫고,
그다음 `sort:recent`를 되돌려 놓고, 그다음 목록으로 돌아갑니다.

### 대기 중인 리뷰 {#waiting-reviews}

Pane 아래쪽에는 제거된 브랜치의 리뷰를 포함해 이 머신의 모든 저장소에서
대기 중인 Human 리뷰가 최신순으로 나열되며, 각각
eval, 프로젝트와 브랜치, 기다린 시간, 맡은 사람이 나옵니다. 대기 중인 리뷰가 없으면 이
영역은 **Waiting (0)**이라고 적힌 얇은 막대입니다. 대기 중인 리뷰가 생길 때마다 행이 하나씩
추가되고, 영역은 아래에서 위로 늘어나 Pane 높이의 절반까지 커집니다. 그보다 많아지면 목록이
스크롤됩니다. 하나를 클릭하거나 Enter를 누르면 Main area에 [리뷰](#human-reviews)가 열립니다.
같은 Human 실행에 합류한 요청은 리뷰 하나로 묶여 표시됩니다. 팔로워를 열면
원래 리뷰가 열립니다.

다른 곳에서 만든 새 Run, 결과, 맡기, 제출, 그리고 추가되거나
제거된 워크트리는 직접 다시 읽지 않아도 나타납니다.

## Main area {#main-area}

Main area는 Pane에서 고른 것을 보여 줍니다. Run, 브랜치의 Current,
리뷰, ID로 연 요청, 또는 Settings입니다. 아무것도 고르지 않았거나, 불러오는 중이거나,
오류가 났거나, 그래프가 비어 있으면 그래프 자리는 그대로 두고 그렇다고 알려 줍니다. 다른 Run을 읽을 수 없는 등
이 머신의 기록을 읽는 데 문제가 있으면, 그래프를 옮기거나 가리지 않고 Main area 머리말에
한 줄로 나옵니다. 클릭하면 전체 내용이
나옵니다. 그렇게 읽기에 실패한 뒤에는 마지막으로 읽은 내용이 화면에 남아
오래된 것일 수 있으니, 원인을 고친 뒤 새로 고치세요(Ctrl+R). 선택한 Run 자체를
읽을 수 없게 되거나 그 그래프를 불러오지 못하는 경우는 다릅니다. 메시지가 그래프
자리를 대신하며, 다른 것을 고르면 됩니다. 손상된 기록은
성공한 증거로 취급하지 않고 [읽을 수 없음으로 표시합니다](../features/others/state.md#unreadable-records).

### Run {#run}

Pane에서 Run을 고르면 Main area에 그 Run의 Artifact와 판정을 그래프로 보여 주고, 그 위에 Run 머리말과 주의 항목을 보여 줍니다. 노드와 관계의 색은
리뷰 상태(GREEN, 실행 중이거나 Human 대기, 대기, RED, ERROR, 막힘)를 보여 주며
결과가 도착하는 대로 그 자리에서 색이 바뀝니다. 의존성은 그래프의
입력→소비자 관계와, Artifact나 eval의
**Debug** 아래의 **Waits for**로 확인하세요. Run 종료 시 검증은 과거 기록으로 남습니다. 이후의 Human 제출은
이전 판정을 다시 쓰지 않고 현재 요청 표시를 바꿀 수 있습니다. Run의
머리말을 클릭하거나 팔레트 명령 **Open the Run's Detail**을 쓰면 그 Run의
Detail이 열립니다. 저장된 검증과 충족되지 않은 의무, 요청 수, 대기 중인 작업,
시간, 예산, 실행/재사용된 작업, 사용량입니다. 그곳에서 `t`는 Technical을 켜고 끄며, `w`나
대기 중인 eval 컨트롤은 상위 eval의 결과가 없어 실행이 보류된 검사를 보여 줍니다.

### Current {#current}

브랜치의 **Current**는
[`artifactize status`](../features/run.md#status-and-static-graph)처럼 워크트리의 지금 상태를 스캔하고,
Run 없이 현재 선언의 그래프를 그립니다. 각 Artifact는
reused(모든 eval의 결과가 평가 없이 재사용됨), would run, waiting,
blocked 중 하나로 색칠됩니다. Run의 Artifact처럼 노드에는 이름만 표시하고, 접근성 이름에는
그 Artifact의 상태와 실행될 eval 수를 담습니다. 머리말은 언제 스캔했는지 알려 줍니다.
다시 고를 때, **Refresh**나 Ctrl+R/F5를 누를 때, 그 브랜치의 Run이 끝날 때 다시 스캔합니다.
**Structure and evaluation criteria**를 펼치면 전체 트리, 기준, 라벨 붙은
관계를 텍스트로 볼 수 있습니다. Human [`graph` 도구](../features/tools/builtin.md#current-project-graph)와
`artifactize-desktop graph --repo PATH`는 이 보기로 앱을 엽니다. 연다고 해서
무엇이 승인되지는 않습니다.

### 그래프 {#graphs}

두 그래프, 즉 Run의 그래프와 Current는 모두 포인터로 조작합니다. Tab으로 이름 붙은
Artifact에 초점을 옮기고, 그 위에서 Enter를 누르면 클릭과 같은 동작을 합니다. 그 밖의 그래프 전용 단축키는
없습니다.

그래프 배경을 끌면 이동하고, 휠, 핀치, 배경 더블 클릭으로
보기 영역을 확대하거나 축소합니다. **Zoom In**, **Zoom Out**, **Fit View**도 보기 영역을 바꿉니다.
이 동작은 구분선이나 Detail이 아니라 보기 영역을 움직입니다. 그래프는
처음 나타날 때 전체가 보이며, 그 뒤로는 사용자만 보기 영역을
움직입니다. Detail을 열거나, 바꾸거나, 크기를 조절하거나, 닫아도, 새 결과가 나오거나 다시
스캔하거나 배치가 새로 바뀌어도 확대 비율과 화면 위치는 그대로입니다. **Fit View**는 Detail이 위에 떠 있든 아니든
같은 방식으로, 전체 캔버스에 그래프 전체를 다시 보여 줍니다.

모든 그래프는 상위가 왼쪽에 오도록 한 번에 배치됩니다. 아주 많은
Artifact가 공통으로 쓰는 Artifact(모든 리뷰가 읽는 기준 파일 하나 등)는 왼쪽의 별도 열에
놓이며, 이를 쓰는 각 Artifact로 가는 간선은 그대로 그려집니다. 노드가 40개를 넘으면
이동과 확대/축소가 되는 미니맵이 그래프 탐색을 돕습니다. **Artifact가 500개를 넘으면** 그래프에
미니맵이 없고, 보이는 Artifact가 500개를 넘는 동안에는 이름 없는 색 상자로 보이며 클릭으로만 열 수 있습니다.
확대해서 보이는 수를 줄이면 다시 이름이 나오고 Tab과 Enter로 이동할 수 있습니다.
Run이 바뀌면 그래프의 색이 그 자리에서 바뀌고, Artifact나 간선이 바뀔 때만 다시 배치합니다. Artifact의 Detail은 양쪽에
각각 최대 16개의 이웃을 실패한 것부터 보여 주고, 나머지는 개수만 셉니다.

### Detail {#detail}

Artifact를 클릭하면 그 **Detail**이 열립니다. 그래프 오른쪽 위에 떠 있으며
뒤로 그래프가 계속 보이고, 결코 Pane 옆에 붙지 않습니다. 보기 영역은 그대로 두므로,
Detail 아래에 가려진 Artifact를 보려면 이동하세요.
다른 Artifact를 클릭하면
그 Artifact의 Detail이 표시됩니다. 그래프
배경, **Close**, Esc, ←를 누르면 닫힙니다. Human 리뷰의 Detail에서 ←는 편집하거나 실행하는
것이 없을 때만 Detail을 닫습니다. 나머지 셋은 누를 때마다 한 단계씩 되돌립니다. 먼저 진행 중인 작업을 취소하고, 그다음 양식을 떠나고, 그다음에야
Detail을 닫습니다. Detail의 왼쪽 가장자리를 드래그해, 내용을 읽기 편하면서도 그래프가 조금 보이는 너비로 조절하세요. 그 폭은 다음 실행에서도 유지됩니다.

Artifact의 Detail에는 Artifact 이름과 eval을 경로 형태로 나열한 칩 `[icon] {name} / [eval] …`이 있습니다.
Artifact를 나타내는 칩 하나와 eval마다 판정의 기호와 색을 표시하는 칩이 하나씩 있으며, Current에서는 실행 또는 재사용 여부를 보여 줍니다.

Artifact 칩에서는 그 Artifact를 가운데 두고 이웃과의 관계를 그래프의 노드와 간선으로 보여 줍니다.
왼쪽에는 이 Artifact의 eval이 사용하는 Artifact가, 오른쪽에는 이 Artifact를
사용하는 eval이 속한 Artifact가 있습니다. 그림은 움직이지 않으며, 이웃을 클릭하면 그 이웃의
Detail이 열립니다. 그 아래에는 판정과 함께 그 eval들(하나를 클릭하면 그 칩이 나옴), 그
**Tools**, 그리고 경로가 있습니다. 대기 중인 의존성을 포함한 나머지 정보는 모두 **Debug** 아래에 접혀 있습니다.

**Tools**는 Artifact가 선언한 [Human 도구](../features/tools/human.md)이며,
리뷰에서처럼(아래) `▶ operation` 버튼으로 나오며, 리뷰와 마찬가지로 전용 **Tool log**가 있습니다. 클릭하면
보여 주고 있는 Run과 관계없이 그 브랜치의 현재 워크트리에서 요청을 맡지 않은 채 도구 하나를 바로
실행하며, 실행 결과는 리뷰 증거로 남기지 않습니다. 도구 하나가
실행되는 동안 같은 Artifact의 다른 도구 버튼은 비활성화되며, 이름 옆의 **Cancel** 버튼으로
실행을 멈출 수 있습니다. Detail을 닫아도 멈추지 않으며, 출력은 계속
Artifact의 Tool log에 도착해 Detail을 다시 열면 보입니다. 실행 기록은 앱이 실행되는 동안
그 Tool log에 남습니다. 그래프의 노드에는 도구 버튼이 없습니다.

eval의 칩은 **Summary**를 보여 줍니다. 상태와 함께, 실행에 든 시간과 토큰(`k`나 `M` 단위), 사용한 모델,
또는 재사용으로 아낀 것, 지시문,
결과(지적 사항은 `item`과 `where`를 제목으로 붙인 번호 목록), 그리고 있으면
**Execution options**, **Execution metadata**, **Fingerprint**가 나옵니다.
Current에서는 eval이 실행될지 재사용될지와 그 이유, 그리고 재사용할 결과를
보여 줍니다. 그 밖의 정보는 **Debug** 아래에 접혀 있으며, Artifact나 Human이 아닌 eval의 Summary에서
`t`로 보이거나 숨깁니다. 로그가 있는 eval은 칩 아래에서
먼저 보이는 Summary와 로그 사이를 오갈 수 있습니다. 일반 텍스트 선택지이며, 고른 보기가
굵고 대비가 높게 표시됩니다. Agent eval의 **Agent log**(대화. 별도의 스크롤 막대가 있음) 또는 runtime eval의 **Runtime log**(저장된 stdout/stderr. 실시간
로그 스트림이 아님)입니다. 대화가 없거나 원격에만 있으면
이 머신에서 볼 수 없는 이유를 보여 줍니다. Run 안의 Human eval 칩에는 리뷰와 승인이 들어 있으며,
아래에 설명한 컨트롤이 있습니다. 일부 eval만 골라 `verify`를 실행했을 때처럼, Run에서 선택하지
않은 eval에는 그 Run의 요청이 없습니다. 그 칩은 결과의 Summary, Human 컨트롤, Tool log 없이
섹션을 읽기 전용으로 보여 줍니다.

Agent log는 실시간으로 갱신됩니다. 초점이 있는 Agent log에서 ↑/↓ 또는 `j`/`k`는 행 단위로,
PgUp/PgDn은 페이지 단위로 이동하고, Home/End나 **Top/Bottom**은 양 끝으로 가며, 마우스 휠은
스크롤합니다. 위로 이동하면 따라가기를 멈추고, Bottom으로 돌아가면 새 메시지를 따라갑니다.
Space나 Enter로 화면에 보이는 묶음을 펼치거나 접을 수 있으며, 묶음 제목을 클릭해도
같습니다. 숨겨진 reasoning은 보이지 않고, 공개 reasoning 요약만 보입니다.

### ID로 요청 열기 {#requests-by-id}

Ctrl+O 또는 팔레트의 **Open a request by ID**는 어느
저장소의 저장된 요청이든 Main area에 엽니다. 대기 중인 Human 리뷰는 Pane에서 열 때처럼 조작할 수 있고,
다른 요청은 읽기 전용입니다. 끝난 Human 요청은 Human 리뷰 화면에 읽기 전용으로 열리며, `t`가
Technical을 보이거나 숨깁니다. 로그가 있는 다른 읽기 전용 요청은 eval의 칩처럼 Summary와 Agent
또는 Runtime 로그 사이를 오가며, `t`는 **Debug** 정보를 보이거나 숨깁니다. **Close**는 Pane으로 돌아갑니다. 다른 곳에서 일어난
요청의 변경을 따라가며, Ctrl+R이나 F5로 다시 열지 않고 다시 읽을 수 있습니다.

## Human 리뷰 {#human-reviews}

Pane에서 대기 중인 리뷰를 고르거나 ID로 열면 Main area에 Human
리뷰 화면이 표시되고, 그 위쪽에 eval과 Artifact가 나옵니다. 브랜치나 타임라인 항목을 고르면 리뷰 상태를 유지한 채 그 화면으로 바뀝니다. 열린 양식은 초안을 유지하고, 실행 중인 리뷰 작업은 계속됩니다. Esc는
실행 중인 작업을 취소하고 양식을 떠난 뒤 Pane으로 돌아갑니다.

리뷰를 열기만 해서는 아무것도 맡지 않습니다. `c`로 맡고 `u`로 놓습니다. 다른
사람이 맡은 요청에서는 도구를 실행하거나 결과를 제출할 수 없습니다. 맡기는 계정을 인증하는 기능이 아니라 리뷰어끼리 작업이 겹치지 않게 하는 잠금이며, 요청을 맡은 사람만 도구를 실행하거나 결과를 제출할 수 있습니다. 공통 수명 주기와 미룬 승인은
[Human](../features/human.md)을 보세요.

Human 리뷰 화면에는 위에서부터 지시문, 쓸 **Tools**, 그 **Tool log**,
작성할 **Result**가 차례로 표시됩니다. 지시문은
리뷰 본문의 공유 스크롤 영역 안에 전부 나오므로, 긴 기준은 그 본문을 스크롤해 읽으세요.
`t`는 Human 요청의 Technical 기록을 켜고 끕니다. Tab이나 클릭은
Tools로 이동하고, Ctrl+U는 편집 중에도 맡기를 해제합니다.

도구는 그 도구를 선언한 Artifact별로 묶이며, 리뷰 대상 Artifact가 먼저 옵니다.
각각은 설명이 붙은 `▶ operation` 버튼이며, 실행할 수 없으면 그 이유가 붙습니다.
**클릭하거나, 초점이 있는 버튼에서 Enter나 Space를 누르면 바로 실행됩니다**. Tab은
버튼 사이를 이동합니다. launch 도구는 애플리케이션을 시작하자마자 호출을 마치며,
도구 실행에 실패하면 판정을 기록하지 않고 오류만 표시합니다. 동작을 실행하기 전에 저장된 정의가
여전히 일치해야 합니다.

이 리뷰에서 도구를 실행할 때마다 [Tool log](../features/tools/human.md#tool-log)에
실행 내역이 바로 추가되며, 시작 시각은 로컬 시간으로 표시됩니다. Tool log에서는 긴 줄이 화면 너비에 맞게 줄바꿈되고, 새 출력이 오면 최신 줄이 보이도록 자동으로 스크롤됩니다. 위로 스크롤해 읽으면 그 자리에 머물고,
맨 아래로 다시 스크롤하면 다시 따라갑니다. 그 텍스트는 선택할 수 있는 일반
텍스트이므로, 도구가 출력한 내용을 결과에 복사하세요. 로그는 앱이 실행되는 동안 유지되며
이 창에서 제출하면 지워집니다. CLI나
다른 창에서 결과를 제출하면 이 창의 편집은 끝나지만 로그는 그대로 남습니다. 아무것도
저장되지 않습니다.

요청을 맡은 뒤 `g`는 GREEN을, `r`은 RED를 엽니다. 각각 eval의
스키마로 만든 양식입니다([쓸 수 있는 형태](../features/declarations.md#human-result-schemas)).
텍스트 상자, 숫자 상자, true/false, 선택지, 항목마다 **+ Add**와
✕가 있는 텍스트 목록, 또는 그룹을 위한 **+ Add**와 그룹마다 ✕가 있는 필드의 반복 그룹입니다
(입력할 수 있도록 빈 그룹 하나는 언제나 남음). 상수는 채워져 있고
보이지 않습니다. `*`는 필수 필드를 표시합니다. 비어 있는 선택 텍스트나 숫자 필드(텍스트
목록 항목 포함)에는 회색으로 *Optional*이 나오고, 선택적인 예/아니요나 선택지는 정하지 않은 동안 `–`를
보여 줍니다. Tab은 컨트롤 사이를 이동합니다. Ctrl+G/Ctrl+R은 판정을 바꿉니다. 필드 안에서 Enter는
제출하지 않습니다. Ctrl+S를 누르거나 **Submit** 버튼을 누르면 제출되며, 버튼에 키보드 초점을 두고 Enter를 눌러도 제출됩니다.
스키마 오류는 실패한 경로를 알려 주고 양식을 고칠 수 있게 둡니다. 입력기로 한국어 등을 조합하는 동안에는 텍스트 입력만 처리하고 단축키는 실행하지 않습니다.
Esc를 누르면 진행 중인 작업이 취소되고, 다시 누르면 양식 편집이 끝나며, 한 번 더 누르면 리뷰에서 나갑니다.
양식을 떠나도 그 판정의 초안은 유지되며, 다시 열면 그 초안이 돌아옵니다.
GREEN과 RED는 초안을 따로 유지합니다. 같은 요청을 Pane에서 열든 Run의 Detail에
있는 칩에서 열든 같은 초안과 Tool log가 보입니다. 백업을 복원하는 등으로 상태 디렉터리가 교체되면
열린 리뷰를 닫고, 실행 중인 Human 도구와 제출을 취소하며, 저장하지 않은 초안과 Tool log를
버립니다.

완료된 결과는 열린 채로 남습니다. 원격 게시는 **로컬 확정 뒤에**
실패할 수 있습니다. 그러면 양식이 닫히고 로컬에 저장되었다는 알림이 그 실패를 설명합니다.
판정은 이미 기록되었으니, 다시 제출하지 말고 Settings의 **Push results**
(또는 `artifactize remote push`)로 게시를 다시 시도하세요.

### 떠나기와 종료 {#leave-and-quit}

`q`는 텍스트 필드 밖에서 종료합니다. 다만 키보드 초점이
Human 리뷰에 있고 편집이나 작업이 진행 중이면 종료하지 않으니, 먼저 편집을 마치거나 진행 중인 작업을 취소하세요. Commands를 닫은 뒤처럼
키보드 초점이 다른 곳에 있으면, 그 리뷰가 열려 있어도 `q`가 종료를 시작합니다.
창을 닫아도 종료가 시작됩니다. 이 창에서 맡은 Human 요청 중 아직 제출하지도, 맡기를 해제하지도 않은 요청이 있다면
**Stay**(Esc), **Release and quit**(`u`), **Keep and quit**(`k`) 중에서 고르세요.
맡기를 유지하면 요청은 이 리뷰어가 맡은 상태로 남을 뿐, 판정이 제출되지는 않습니다. 확인 창에는
이 창에서 맡은 요청이 마지막으로 조회한 상태를 기준으로 나열됩니다. CLI나 다른 창에서
놓거나 확정한 요청이 여전히 나열될 수 있고, 창이 열리기 전에 맡은 요청은
나열되지 않습니다. 종료하면 아직 출력을 내고 있는 도구와 진행 중인 리뷰 작업을 취소합니다. launch
도구가 연 프로그램은 계속 실행되니 직접 닫으세요.

## Settings {#settings}

Settings는 Main area에 나옵니다. **Settings** 버튼이나 Ctrl+,를 다시 누르면
Main area가 보여 주던 것으로 돌아가며, 텍스트 필드나 선택 목록 밖에서의 Esc도
마찬가지입니다(그 안에서 Esc를 누르면 초점은 그 필드에 그대로 있습니다). 대신 Pane에서 브랜치, 칩, 리뷰를 고르면
고른 항목을 보여 줍니다. Settings는 보일 때 계정/저장소 정보를
다시 불러옵니다. 다시 불러오려면 다시 열거나 팔레트의 **Refresh settings** 명령을 쓰세요.

- **API keys:** OpenAI와 Anthropic 키 환경 변수가 설정되어 있는지만
  보고하며, 그 값은 결코 보여 주지 않습니다. 앱을 실행하는 환경에서 설정하세요.
- **Codex:** 로그인 안 됨, artifactize가 저장한 토큰과 만료 시각, 읽기 전용
  `ARTIFACTIZE_CODEX_AUTH_FILE`, 또는 저장이 거부된 이유를 보여 줍니다. 저장된 액세스 토큰이 만료되면 다음에 쓸 때 갱신되고, 외부 파일의 토큰이 만료되면 Codex에 다시 로그인해야 합니다.
  외부 파일 모드와 저장 거부 모드에서는 여기서 로그인할 수 없으며, 로그아웃은
  artifactize가 저장한 계정에서만 쓸 수 있습니다. 브라우저 로그인은
  취소할 수 있고, 브라우저가 돌아오지 못하면 리디렉션 URL을 붙여 넣을 수 있습니다.
  다른 프로세스가 포트 1455를 쓰고 있으면 앱이 붙여 넣기가 필요하다고 알려 줍니다.
  로드에 실패한 뒤 브라우저 주소 표시줄에서, 또는 계속 로딩 중이면 개발자 도구 → Network에서
  전체 `http://localhost:1455/auth/callback?code=…` URL을 복사해
  Settings에 붙여 넣은 다음 **Finish sign-in**을 고르세요.
  로그아웃하면 로컬 토큰이 삭제되며, 서버에서 토큰이 폐기됐는지 확인할 수 없으면 경고합니다.
- **Models:** 고른 백엔드가 제공하는 모델 ID를 나열합니다.
- **Review store:** URL, 토큰, 공유 수준으로 로그인하고, 상태를 보여 주고,
  결과를 푸시하며(또는 시험 실행), 로그아웃합니다. **Summary**는 호출 세부 사항,
  캡처한 출력, 도구 호출 이력을 빼고, **Full**은 저장된 실행도 보냅니다.
  Summary도 리뷰 메타데이터, 소유자 결과, 선언된 Runtime 명령과
  인자, Agent 실행 경로 메타데이터는 공유합니다. 그 선언에는 경로나 민감한 리터럴이 들어 있을 수 있으며, Summary를 골라도 이런 정보가 자동으로 가려지지는 않습니다. 팀의
  개인정보 요구에 맞게 고르세요. 로그아웃은 로컬 설정을 제거할 뿐, **서버
  토큰은 제거하지 않습니다**. 저장소 관리자가 [그 토큰을 폐기](../cli/review-store.md#review-store-server)해야 합니다.
  [공유와 푸시 동작](../cli/review-store.md#remote-review-store-client)을 보세요.

Settings는 CLI와 같은 계정과 저장소 작업을 씁니다. 자격 증명은
`.artf`에 넣지 않습니다.
