# 데스크톱 {#desktop}

앱을 열면 이 머신에서 Run을 실행한 모든 프로젝트의 현재 브랜치와, 승인이 필요한 모든 Human
리뷰를 한 화면에서 볼 수 있습니다. Run을 살펴보고, 각 브랜치에서 지금 검증하면 실행될 작업과 증거를
확인한 뒤 Human 승인을 처리하세요. 앱은 CLI, TUI와 상태를 공유하므로 한쪽에서 변경한 내용이
다른 쪽에도 반영됩니다. 앱은 릴리스마다 명령과 함께 배포되며, 설치 방법은 [데스크톱 앱](../getting-started/install-options.md#desktop-app)을 보세요.

첫 실행 때의 명령 설정, PATH 세부 사항, 업데이트, 정리는
[설치 안내](../getting-started/install-options.md#desktop-app)를 보세요.

## 앱 열기 {#open-the-app}

```sh
artifactize-desktop
artifactize-desktop monitor --repo PATH
artifactize-desktop review [REQUEST_ID]
artifactize-desktop graph --repo PATH
```

인자가 없으면 현재 디렉터리와 상관없이 아무것도 고르지 않은 채 앱이 열립니다.
`--repo PATH`는 그 폴더의 브랜치를 고르고 펼친 뒤 가장 최근 항목을 보여 줍니다. 기본값인 `--all`은
아무것도 고르지 않으며, 어느 쪽이든 모든 브랜치가 나열됩니다. `review`는
가장 최근에 승인 대기 상태가 된 Human 리뷰를, `review REQUEST_ID`는 지정한 요청을 엽니다. `review`는 `--repo`를 주어도 브랜치를 고르거나 펼치지 않습니다. `graph`에는
`--repo`가 필요하며 그 브랜치의 [Current](#current)를 보여 줍니다. `--state-dir PATH`로
상태 디렉터리를 지정하며, 지정하지 않으면 공유 상태 디렉터리를 씁니다. `--reviewer NAME`으로
협업할 때 리뷰어로 표시할 이름(보통 사용자 이름)을 지정합니다. `-h`나 `--help`(모드 뒤에도
쓸 수 있음, 예: `artifactize-desktop monitor --help`)와 `artifactize-desktop help [MODE]`는 잘못된 인자와
마찬가지로 stderr에 도움말을 출력하고 2로 종료합니다. 앱을 정상적으로 닫으면 종료 코드는 0이고, 시작하지 못하면
1입니다.

아래 단축키는 Ctrl을 기준으로 적었습니다. macOS에서는 Ctrl 대신 기본 보조 키인 Command를 누르세요.
Ctrl+K나 F1을 누르거나 **Commands** 버튼을 클릭하면 명령을 검색할 수 있는 팔레트가 열립니다. Enter를 누르면 명령이 실행되고, Esc를 누르면 팔레트가 닫힙니다. Ctrl+,를 누르거나 **Settings** 버튼을 클릭하면 화면 위에 [Settings](#settings)가 열립니다. Ctrl+O를 누르면 ID로 요청을 열 수 있습니다. `?`를 누르면 지금 초점이 있는 곳에서 쓸 수 있는 키가 나옵니다. Ctrl+R 또는 F5를 누르면 디스크에서 상태를 다시 읽고 브랜치를 다시 스캔합니다. Current에서는 해당 워크트리도 다시 스캔합니다. 키보드 초점이
Human 리뷰에 있고 진행 중인 작업이 없으면, 양식이 열려 있든 아니든 Ctrl+R은 새로 고침 대신 RED 명령으로 동작합니다.
요청을 맡았으면 RED를 열거나 RED로 바꾸고, 그렇지 않으면 먼저 리뷰를 맡아야 한다고
알려 줍니다. 완료되어 읽기 전용인 Human 리뷰에서는 Ctrl+R이 아무 동작도 하지 않습니다. 두 경우 모두 상태를 다시 읽으려면 F5나 팔레트의 **Refresh**를 쓰세요.
앱은 시스템의 라이트 모드 또는 다크 모드 설정을 따릅니다.

[새 릴리스](../getting-started/update.md#newer-releases)가 나오면 헤더의 **Settings** 앞에
`VERSION available`이 나타납니다. 클릭하면 대화상자가 열리고, 이 앱의 버전과 앱을 설치한
방법에 맞는 업데이트 방법을 보여 줍니다. 실행할 명령은 선택해서 복사할 수 있는 텍스트로,
직접 내려받아 설치할 파일은 링크로 보여 주고, 설치 방법을 알 수 없으면 릴리스 페이지를
안내합니다. 링크는 브라우저에서 열리고, Esc나 **Close**로 대화상자를 닫습니다. 앱은 시작할 때와
실행 중 하루에 한 번 새 릴리스를 확인하며, 스스로 업데이트하지는 않습니다. Microsoft Store로
설치한 앱은 Store가 업데이트하므로 이 알림이 나타나지 않습니다.

마우스를 올리면 강조만 되고, 자세한 정보는 클릭해야 열립니다.

## Pane {#pane}

앱 화면은 왼쪽의 **Pane**과 그 옆의 **Main area**로 나뉩니다.
Pane의 항목은 세로로 한 줄씩 배치됩니다. 맨 위에 검색 칸, 그 아래에 브랜치, 그리고
맨 아래에 사람의 승인이 필요한 리뷰가 있습니다. Pane과
Main area 사이의 구분선을 끌어 크기를 바꾸세요. Main area에 무엇이 표시되든 직접 조절한 비율이 그대로 유지됩니다.

### 브랜치 {#branches}

브랜치는 Git 저장소의 작업 이력을 나누어 관리하는 단위입니다. 워크트리는 브랜치 하나를 체크아웃해 작업하는 폴더입니다. 한 저장소에 워크트리를 여러 개 둘 수 있습니다. 각 워크트리에서는 브랜치를 체크아웃해 작업하거나, 브랜치에 연결되지 않은 특정 커밋을 체크아웃할 수 있습니다. 각 항목은 `artifactize / feat/x`처럼
프로젝트와 브랜치로 표시됩니다. 각 항목에는 현재 워크트리와 체크아웃한 브랜치를 표시하고, 분리 상태이면 브랜치 대신 폴더 이름을 표시합니다. Git으로 관리하지 않는 프로젝트는 폴더 이름으로 표시합니다.
나열되는 프로젝트는 이 머신에 Run이 있는 프로젝트와 `--repo`나 `graph --repo`로 앱을 시작한
프로젝트입니다. `--repo`로 시작한 프로젝트는 아직 Run이 없어도 나열됩니다. 제거된
워크트리나 폴더, 또는 Git이 더 이상 나열하지 않는 워크트리는 보이지 않습니다. 추가되거나 제거된 워크트리는
다시 읽지 않아도 몇 초 안에 나타나거나 사라집니다. Run을 실행한 쪽이 에이전트 세션이든 사람이든
따로 항목이 생기지는 않습니다. 각 브랜치에는 실행한 폴더와 관계없이 그 프로젝트의 해당 브랜치에서 실행한 Run이 나옵니다.

브랜치가 접혀 있으면 이름 아래에 가장 최근 Run의 상태를 나타내는 색 점과 상태 이름,
실행 후 경과 시간(실행 중이면 지금까지 걸린 시간)을 표시합니다. 브랜치를 클릭하면
펼치고 가장 최근 항목을 보여 줍니다. 이름 앞의 꺾쇠를 클릭하면 Main area는 바뀌지 않고
그 항목만 펼쳐지거나 접힙니다. 펼치면 타임라인이 Run을 최신순으로 나열하며, 각 Run에는
상태, 경과 시간, Run ID가 나옵니다. verify를 요청할 때 [코멘트](../cli/index.md#submission-and-watching)를
남긴 Run은 Run ID 아래에 그 코멘트를 한 줄로 요약해 표시합니다. 맨 앞 항목은 워크트리의 지금 상태인 **Current**입니다. Run이
진행 중이면 그 Run이 Current 자리에 오고, Run이 끝나면 Current가 다시 표시됩니다. 끝의 **Older runs**는
더 오래된 Run을 가져옵니다. 항목을 클릭하면 회색의 둥근 배지로 표시되며 Main area에 나옵니다. 브랜치는
몇 개든 펼칠 수 있으며, `monitor`나 `graph`로 시작할 때 지정한 브랜치는 펼친 채로 시작합니다.

브랜치 이름 끝의 ☆를 클릭하면 별표를 추가합니다. 별표가 있는 브랜치가 먼저 나오고,
두 그룹은 각각 검색 순서대로 정렬됩니다. 별표는 앱을 다시 열어도 남아 있습니다.
별표를 떼려면 ★를 다시 클릭하세요.

↑/↓ 또는 `j`/`k`로 브랜치, 펼친 브랜치의 타임라인, 대기 중인 리뷰 사이를 이동할 수 있습니다. 브랜치로 이동하면 그 브랜치의 가장 최근 항목을, 타임라인 항목이나 리뷰로 이동하면 해당 항목을 보여 줍니다. →를 누르면 선택한 브랜치가 펼쳐지거나 그 타임라인으로 들어가며, ←를 누르면 타임라인에서 빠져나오거나 브랜치가 접힙니다. 타임라인의
가장 오래된 항목에서 ↓를 누르면 더 오래된 Run을 가져옵니다. Enter를 누르면 Main area로 이동하고, 그곳에서 Detail이 열려 있지 않을 때 Esc를 누르면 Pane으로 돌아갑니다.

### 검색 {#search}

`/`를 누르면 검색 칸으로 이동합니다. Pane에 있거나 그래프가 보이지 않을 때는 Ctrl+F도 같습니다.
그래프가 보일 때 Ctrl+F를 누르면 [그래프에서 찾기](#find-in-the-graph)가 열립니다. 처음 검색어는 `sort:recent`입니다. 일반 검색어와
`key:value` 조건을 모두 만족하는 브랜치와 대기 중인 리뷰만
표시합니다. 일반 검색어는 대소문자를 구분하지 않으며, 프로젝트, 브랜치, 대기 중인 리뷰의 eval 이름에 그 검색어가 들어 있는 항목을 찾습니다. `repo:`와 `branch:`는 각각 저장소와 브랜치 필드에 그 검색어가 들어 있는 항목을 찾습니다. 값에 공백이 있으면 `repo:"my project"`처럼 따옴표로 묶으세요. 따옴표 안의 공백은 새 검색어를 시작하지 않고 그 값에 포함됩니다.
`sort:recent`는 가장 최근 Run이 있는 브랜치를 맨 앞에, Run이 없는 브랜치를
맨 뒤에 두고, `sort:name`은 프로젝트와 브랜치 순으로 정렬합니다. 자동 완성으로 검색 키와
값을 채울 수 있습니다. 검색어가 비어 있거나 커서가 공백 바로 뒤에 있을 때 ↓를 누르면 검색 키 후보가 표시됩니다. ↑/↓로 후보를 고른 뒤 Tab이나 Enter를 누르거나 후보를 클릭하면
검색어에 들어갑니다. 자동 완성 후보가 떠 있지 않을 때 Enter를 누르면 목록으로 돌아갑니다. 알 수 없는 키 등으로 검색어를 해석할 수 없으면 브랜치 목록 대신 오류를 보여 주고, 검색어를 고칠 때까지 두 목록을 비워 둡니다. Esc를 누를 때마다
자동 완성 후보를 닫고, 검색어를 `sort:recent`로 되돌리고, 목록으로 돌아가는 순서로 동작합니다.

### 대기 중인 리뷰 {#waiting-reviews}

Pane 아래쪽에는 제거된 브랜치의 리뷰를 포함해 이 머신의 모든 저장소에서
대기 중인 Human 리뷰가 최신순으로 나열되며, 각각
eval, 프로젝트와 브랜치, 대기 시간, 맡은 사람이 나옵니다. 대기 중인 리뷰가 없으면 이
영역은 **Waiting (0)**이라고 적힌 얇은 막대로 줄어듭니다. 대기 중인 리뷰가 생길 때마다 행이 하나씩
추가되고, 영역은 아래에서 위로 늘어나 Pane 높이의 절반까지 커집니다. 그보다 많아지면 목록이
스크롤됩니다. 하나를 클릭하거나 Enter를 누르면 Main area에 [리뷰](#human-reviews)가 열립니다.
같은 Human 리뷰를 공유하는 요청은 하나의 리뷰로 묶어 표시합니다. 그런 요청을 열면
원래 리뷰가 열립니다.

다른 곳에서 만든 새 Run, 결과, 담당 지정, 제출, 그리고 추가되거나
제거된 워크트리는 직접 다시 읽지 않아도 화면에 반영됩니다.

## Main area {#main-area}

Main area는 Pane에서 고른 것을 보여 줍니다. Run, 브랜치의 Current,
리뷰, 또는 ID로 연 요청입니다. 아무것도 고르지 않았거나, 불러오는 중이거나,
오류가 났거나, 그래프가 비어 있으면 그래프 자리에 그 상태를 알리는 메시지가 나옵니다. 다른 Run을 읽을 수 없는 등
이 머신의 기록을 읽는 데 문제가 있으면, 그래프를 옮기거나 가리지 않고 Main area 헤더에
문제를 알리는 메시지가 한 줄로 표시됩니다. 메시지를 클릭하면 전체 내용을 볼 수 있습니다. 읽기에 실패하면 마지막으로 불러온 내용이 그대로 남아 실제 상태와
다를 수 있으니, 원인을 해결한 뒤 새로 고치세요(Ctrl+R). 선택한 Run 자체를
읽을 수 없게 되거나 그 그래프를 불러오지 못하는 경우는 다릅니다. 메시지가 그래프
자리를 대신하며, 다른 것을 고르면 됩니다. 손상된 기록은
검증을 통과했다는 근거로 삼지 않고 [읽을 수 없는 기록으로 표시합니다](../features/others/state.md#unreadable-records).

### Run {#run}

Pane에서 Run을 고르면 Main area에 그 Run의 Artifact와 판정이 그래프로 표시됩니다. 그 위에는 Run 헤더와 주의 항목이 표시되고, Run에 코멘트가 있으면 전문도 함께 표시됩니다. 노드와 관계의 색은
리뷰 상태(GREEN, 실행 중 또는 Human 승인 대기, 의존성 대기, RED, ERROR, BLOCKED)를 보여 주며
결과가 도착하는 대로 그 자리에서 색이 바뀝니다. 의존성은 그래프의
입력 → 사용처 관계와, Artifact나 eval의
**Debug** 아래의 **Waits for**로 확인하세요. Run이 끝날 때의 검증 결과는 기록으로 남습니다. 나중에 Human 판정을 제출해도
이전 Run의 판정은 바뀌지 않고, 현재 요청의 상태 표시만 바뀔 수 있습니다. Run의
헤더를 클릭하거나 팔레트 명령 **Open the Run's Detail**을 쓰면 그 Run의
Detail이 열리며, 저장된 검증과 충족되지 않은 최종 검증 요건, 요청 수, 대기 중인 작업,
시간, 예산, 실행·재사용된 작업, 사용량을 확인할 수 있습니다. 그곳에서 `t`를 누르면 Technical이 표시되거나 숨겨집니다. `w`를 누르거나 대기 중인 eval 컨트롤을 사용하면 상위 eval의 결과가 없어 실행이 보류된 eval을 볼 수 있습니다.

### Current {#current}

브랜치의 **Current**는
[`artifactize status`](../features/run.md#status-and-static-graph)처럼 워크트리의 지금 상태를 스캔하고,
Run 없이 현재 선언의 그래프를 그립니다. 각 Artifact는 처음에 확인 중(checking)으로 표시되다가,
지금 verify를 실행하면 어떻게 될지에 따라 색이 바뀝니다. reused(모든 eval에서 기존 결과를 재사용), would run,
waiting, blocked 중 하나입니다. 스크린 리더는 Artifact마다 이 상태와 실행될 eval 수를 읽어 줍니다.
헤더에는 아직 확인 중인 Artifact 수가 나오고, 스캔이 끝나면 스캔한 시각이, 실패하면 그 이유가 나옵니다.
Current는 다시 고를 때, 그 브랜치의 Run이 끝날 때, **Refresh**나 Ctrl+R/F5를 누를 때 다시 스캔합니다.
스캔이 아직 진행 중일 때 Current를 다시 고르거나 Run이 끝나면 진행 중인 스캔을 이어 갑니다. **Refresh**나
Ctrl+R/F5를 누르면 그 스캔이 끝난 뒤 다시 스캔하므로, 그사이 바꾼 파일도 반영됩니다.
검색 때문에 브랜치가 Pane에 보이지 않으면 Run이 끝난 뒤 **Refresh**를 누르세요.
**Structure and evaluation criteria**를 펼치면 전체 트리와 평가 기준, 이름이 붙은 관계를 텍스트로 확인할 수 있습니다. Human [`graph` 도구](../features/tools/builtin.md#current-project-graph)와
`artifactize-desktop graph --repo PATH`는 이 보기로 앱을 엽니다. 이 보기를 열기만
해서는 어떤 리뷰도 승인되지 않습니다.

### 그래프 {#graphs}

Run의 그래프와 Current 그래프는 모두 마우스로 조작합니다. Tab으로 이름 붙은
Artifact에 초점을 옮기고, 그 위에서 Enter를 누르면 클릭과 같은 동작을 합니다. Ctrl+F로
[Artifact나 eval을 이름으로 찾을 수 있습니다](#find-in-the-graph). 그 밖의 그래프 전용 단축키는
없습니다.

그래프 배경을 끌면 이동하고, 휠, 핀치, 배경 더블 클릭으로 확대하거나 축소합니다.
**Zoom In**과 **Zoom Out**도 같은 일을 하고, **Fit View**는 Detail이 위에 떠 있든 아니든 전체
캔버스에 그래프 전체를 보여 줍니다. 처음에는 그래프 전체를 보여 주고, 그 뒤로는
사용자가 직접 조작하거나 찾은 항목을 열 때만 보기 영역이 바뀝니다. Detail을 열거나, 새 결과를 받거나, 다시 스캔하거나, 그래프를 다시 배치해도 보기 영역은 바뀌지 않습니다.

모든 그래프는 상위가 왼쪽에 오도록 한 번에 배치됩니다. 아주 많은
Artifact가 공통으로 쓰는 Artifact(모든 리뷰가 읽는 기준 파일 하나 등)는 왼쪽의 별도 열에
놓이며, 이를 쓰는 각 Artifact로 가는 간선은 그대로 그려집니다. 아래 개수는 그려진 노드 수이며,
여러 Artifact 안에 그려진 부분은 그려진 만큼 셉니다. 노드가 40개를 넘으면
이동과 확대/축소가 되는 미니맵이 그래프 탐색을 돕습니다. **노드가 500개를 넘으면** 그래프에
미니맵이 나오지 않고, 화면과 그 주변에 노드가 500개를 넘게 있는 동안에는 이름 없이 색칠된 사각형으로 표시되며 클릭하거나 [찾기](#find-in-the-graph)로만 열 수 있습니다.
이름이 다시 보일 때까지 확대하면 Tab과 Enter로 이동할 수 있습니다.
Run이 바뀌면 그래프의 색이 그 자리에서 바뀌고, Artifact나 간선이 바뀔 때만 다시 배치합니다. Artifact의 Detail에는 양쪽에 이웃 Artifact가 각각 최대 16개씩 표시됩니다. 실패한 Artifact를 먼저 보여 주고, 나머지는 개수만 표시합니다.

[부분](../features/artifact.md#composition)으로 이루어진 Artifact는 부분들을 감싸는 상자로
그려지고, 상자 위쪽에 이름과 색이 표시됩니다. 부분에 다시 부분이 있으면 그 안에 상자가 하나 더
들어갑니다. 상자가 곧 그 Artifact입니다. 부분이 없는 곳을 클릭하거나 Tab과 Enter를 쓰면 그
Artifact의 Detail이 열리고, 부분을 클릭하면 그 부분의 Detail이 열립니다. 여러 Artifact에 속한
부분은 각 Artifact 안에 하나씩 그려집니다. 그중 하나를 열면 모든 사본이 함께 강조되고, Detail에
몇 번 그려졌는지와 어느 Artifact 안에 있는지가 나옵니다.

### 그래프에서 찾기 {#find-in-the-graph}

Run의 그래프나 Current가 보이고 키보드 초점이 Pane 밖(그래프나 Detail)에 있을 때 Ctrl+F를 누르면
그래프 왼쪽 위에 찾기 칸이 열립니다. 입력한 글자가 이름에 들어 있는 Artifact와 eval을 대소문자 구분 없이
그래프 순서대로 보여 줍니다. Artifact는 전체 이름으로, eval은 `Artifact / eval` 형태로 나오고, 각각
판정 기호와 색이 붙습니다(Current에서는 verify가 할 일). 처음 50개까지 보여 주고, 나머지는 몇 개가 더
있는지만 알려 줍니다. 찾은 항목이 없으면 없다고 표시합니다.

↑/↓로 항목을 고릅니다. Enter를 누르거나(고른 항목이 없으면 첫 항목) 항목을 클릭하면 그 Detail이
열리며, eval이면 그 eval의 탭으로 열립니다. 그 Artifact는 Detail 왼쪽 그래프의 한가운데로 오고,
이름을 읽을 수 있을 만큼 확대됩니다. Esc를 누르면 찾기 칸이 닫히고 키보드 초점이 돌아갑니다. 찾기 칸
바깥을 클릭해도 닫히며, 그 클릭은 평소처럼 동작합니다. 그래프가 너무 커서 이름이 보이지 않을 때도
찾기로 모든 Artifact에 갈 수 있습니다. 여러 Artifact 안에 그려진 부분은 한 번만 나오고, 열면 첫
번째 사본이 가운데로 옵니다.

### Detail {#detail}

Artifact를 클릭하면 그래프 오른쪽 위에 그 **Detail**이 열립니다. Detail 뒤로 그래프가 계속 보이며, Detail은 Pane 옆에 붙지 않습니다.
다른 Artifact를 클릭하면
그 Artifact의 Detail이 표시됩니다. 그래프
배경, **Close**, Esc, ←를 누르면 닫힙니다. Human 리뷰의 Detail에서 ←는 편집하거나 실행하는
것이 없을 때만 Detail을 닫고, 나머지는 [리뷰에서 Esc를 누를 때](#human-reviews)처럼 먼저 한 단계씩 되돌아갑니다. Detail의 왼쪽 가장자리를 드래그해, 내용을 읽기 편하면서도 그래프가 조금 보이는 너비로 조절하세요. 그 폭은 다음 실행에서도 유지됩니다.

Artifact Detail에는 Artifact 이름과 eval을 경로처럼 보여 주는 칩(`[icon] {name} / [eval] …`)이 있습니다.
Artifact를 나타내는 칩 하나와 eval마다 판정의 기호와 색을 표시하는 칩이 하나씩 있으며, Current에서는 실행될지, 재사용될지, 아직 확인 중인지를 보여 줍니다.

Artifact 칩을 선택하면 해당 Artifact를 중심으로 이웃 Artifact와의 관계를 노드와 간선으로 보여 줍니다.
왼쪽에는 이 Artifact의 eval이 사용하는 Artifact가, 오른쪽에는 이 Artifact를
사용하는 eval이 속한 Artifact가 있습니다. 이 그림은 이동하거나 확대할 수 없으며, 이웃을 클릭하면 그 이웃의
Detail이 열립니다. 그 아래에는 이 Artifact의 eval과 판정(클릭하면 그 eval의 칩이 열림),
**Tools**, 경로가 있습니다. 대기 중인 의존성을 포함한 나머지 정보는 모두 **Debug** 아래에 접혀 있습니다.

**Tools**에는 Artifact가 선언한 [Human 도구](../features/tools/human.md)가
아래 리뷰 화면과 같은 `▶ operation` 버튼으로 나오며, 리뷰처럼 전용 **Tool log**도 있습니다. 클릭하면 지금 보고 있는 Run과 무관하게, 그 브랜치의 현재 워크트리에서 도구 하나를 바로 실행합니다. 어떤 요청도 맡지 않으며, 실행 결과는 리뷰 증거로 남지 않습니다. 도구 하나가
실행되는 동안 같은 Artifact의 다른 도구 버튼은 비활성화되며, 이름 옆의 **Cancel** 버튼으로
실행을 멈출 수 있습니다. Detail을 닫아도 멈추지 않으며, 출력은 계속
Artifact의 Tool log에 쌓여 Detail을 다시 열면 보입니다. 실행 기록은 앱이 실행되는 동안
그 Tool log에 남습니다. 그래프의 노드에는 도구 버튼이 없습니다. Tools는 Pane의 검색 결과에
그 브랜치가 남아 있을 때만 보이므로, 검색 때문에 브랜치가 숨겨지면 검색어를 지우거나 넓혀야 다시 나타납니다.

eval의 칩은 **Summary**를 보여 줍니다. 상태와 함께, 실행에 든 시간과 토큰(`k`나 `M` 단위)과 사용한 모델,
또는 재사용으로 절약한 시간과 토큰, 지시문,
결과(지적 사항은 `item`과 `where`를 제목으로 붙인 번호 목록)가 나옵니다. 관련 정보가 있으면
**Execution options**, **Execution metadata**, **Fingerprint**도 함께 표시합니다.
Current에서는 eval이 실행될지, 재사용될지, 아직 확인 중인지와 그 이유, 그리고 재사용할 결과를
보여 줍니다. 그 밖의 정보는 **Debug** 아래에 접혀 있으며, Artifact나 eval의 읽기 전용
Summary(Current의 Human eval 포함)에서 `t`를 눌러 표시하거나 숨길 수 있습니다. 판정을 제출할 수 있는 Human 리뷰에서는 `t`가 **Technical**을 표시하거나 숨깁니다. 로그가 있는 eval은 칩 아래에서
먼저 보이는 Summary와 로그 사이를 오갈 수 있습니다. 전환 버튼에는 텍스트만 표시되며, 선택한
항목은 굵고 진한 글씨로 강조됩니다. 로그는 Agent eval의 **Agent log**(대화. 별도의 스크롤 막대가 있음) 또는 Runtime eval의 **Runtime log**(저장된 stdout/stderr. 실시간
로그 스트림이 아님)입니다. 대화가 없거나 원격에만 있으면
이 머신에서 볼 수 없는 이유를 보여 줍니다. Run 안의 Human eval 칩에는 리뷰와 승인이 들어 있으며,
아래에 설명한 컨트롤이 있습니다. 일부 eval만 골라 `verify`를 실행했을 때처럼, Run에서 선택하지
않은 eval에는 그 Run의 요청이 없습니다. 그 칩은 결과의 Summary, Human 컨트롤, Tool log 없이
섹션을 읽기 전용으로 보여 줍니다.

Agent log는 실시간으로 갱신됩니다. 초점이 있는 Agent log에서 ↑/↓ 또는 `j`/`k`는 행 단위로,
PgUp/PgDn은 페이지 단위로 이동하고, Home/End나 **Top/Bottom**은 양 끝으로 가며, 마우스 휠은
스크롤합니다. 위로 이동하면 자동 스크롤이 멈추고, Bottom으로 돌아가면 새 메시지에 맞춰 다시 자동으로 스크롤됩니다.
Space나 Enter로 화면에 보이는 묶음을 펼치거나 접을 수 있으며, 묶음 제목을 클릭해도
같습니다. 숨겨진 reasoning은 보이지 않고, 공개 reasoning 요약만 보입니다.

### ID로 요청 열기 {#requests-by-id}

Ctrl+O 또는 팔레트의 **Open a request by ID**는 어느
저장소의 저장된 요청이든 Main area에 엽니다. 대기 중인 Human 리뷰는 Pane에서 열 때처럼 조작할 수 있고,
다른 요청은 읽기 전용입니다. 완료된 Human 요청을 열면 Human 리뷰 화면이 읽기 전용으로 표시되며,
`t`를 누르면 Technical이 표시되거나 숨겨집니다. 로그가 있는 다른 읽기 전용 요청을 열면 eval의 칩에서처럼 Summary와 Agent log
또는 Runtime log를 전환해 볼 수 있고, `t`로 **Debug** 정보를 표시하거나 숨길 수 있습니다. **Close**를 누르면 Pane으로 돌아갑니다. 다른 곳에서 일어난
요청의 변경도 화면에 반영되며, Ctrl+R이나 F5로 다시 열지 않고 다시 읽을 수 있습니다.

## Human 리뷰 {#human-reviews}

Pane에서 대기 중인 리뷰를 고르거나 ID로 열면 Main area에 Human
리뷰 화면이 표시되고, 그 위쪽에 eval과 Artifact가 나옵니다. 브랜치나 타임라인 항목을 고르면 리뷰 상태를 유지한 채 그 화면으로 바뀝니다. 열린 양식은 초안을 유지하고, 실행 중인 리뷰 작업은 계속됩니다.
Esc는 한 번에 한 단계씩 되돌아갑니다. 실행 중인 작업을 취소하고, 다음에는 양식에서 나가고, 그다음에는
리뷰에서 나가 Pane으로 돌아갑니다. Detail에서는 Detail을 닫습니다.

리뷰를 열기만 해서는 아무것도 맡지 않습니다. `c`로 요청을 맡고 `u`로 담당을 해제합니다. 다른
사람이 맡은 요청에서는 도구를 실행하거나 결과를 제출할 수 없습니다. 담당 지정은 계정을 인증하는 기능이 아니라 리뷰어끼리 작업이 겹치지 않게 하는 잠금이며, 요청을 맡은 사람만 도구를 실행하거나 결과를 제출할 수 있습니다. Human 요청을 처리하는 공통 절차와 DEFERRED 상태의 승인 요청에 관한 설명은
[Human](../features/human.md)을 보세요.

Human 리뷰 화면에는 위에서부터 지시문, 사용할 **Tools**, 도구의 **Tool log**,
작성할 **Result**가 차례로 표시됩니다. 지시문 전체가
리뷰 본문과 함께 스크롤되므로, 기준이 길면 본문을 스크롤해 읽으세요.
`t`를 누르면 Human 요청의 Technical 기록이 표시되거나 숨겨집니다. Tab을 누르거나 클릭하면 Tools로 이동하며, Ctrl+U를 누르면 편집 중에도 담당을 해제할 수 있습니다.

도구는 그 도구를 선언한 Artifact별로 묶이며, 리뷰 대상 Artifact가 먼저 옵니다.
도구마다 설명이 붙은 `▶ operation` 버튼이 있으며, 실행할 수 없으면 그 이유도 표시됩니다.
**클릭하거나, 초점이 있는 버튼에서 Enter나 Space를 누르면 바로 실행됩니다**. Tab으로 버튼 사이를 이동할 수 있습니다. launch 도구는 애플리케이션을 시작하자마자 호출을 마치며,
도구 실행에 실패하면 판정을 기록하지 않고 오류만 표시합니다. 도구를 실행하려면 현재 선언이 요청에
저장된 정의와 여전히 일치해야 합니다.

이 리뷰에서 도구를 실행할 때마다 [Tool log](../features/tools/human.md#tool-log)에
실행 내역이 바로 추가되며, 시작 시각은 로컬 시간으로 표시됩니다. Tool log에서는 긴 줄이 화면 너비에 맞게 줄바꿈되고, 새 출력이 오면 최신 줄이 보이도록 자동으로 스크롤됩니다. 위로 스크롤해 읽으면 그 자리에 머물고,
맨 아래로 다시 스크롤하면 다시 자동으로 스크롤됩니다. 그 텍스트는 선택할 수 있는 일반
텍스트이므로, 도구가 출력한 내용을 결과에 복사하세요. 로그는 앱이 실행되는 동안 유지되며
이 창에서 제출하면 지워집니다. CLI나
다른 창에서 결과를 제출하면 이 창의 편집은 끝나지만 로그는 그대로 남습니다. 로그는 어디에도
저장되지 않습니다.

요청을 맡은 뒤 `g`를 누르면 GREEN 양식이, `r`을 누르면 RED 양식이 열립니다. 각각 eval의
스키마로 만든 양식입니다([쓸 수 있는 형태](../features/declarations.md#human-result-schemas)).
`*`는 필수 필드를 표시하고, **+ Add**와 ✕로 목록 항목과 그룹을 더하거나 지웁니다. Tab으로 컨트롤
사이를 이동하고 Ctrl+G/Ctrl+R로 판정을 바꿉니다. Ctrl+S를 누르거나 **Submit** 버튼을 누르면
제출되며, 필드 안에서 Enter를 눌러서는 제출되지 않습니다. 스키마 오류가 나면 문제가 된 필드를
알려 주고 양식을 연 채로 두므로 고칠 수 있습니다. 판정마다 초안이 따로 남으며, 양식을 나가거나 다른
곳에서 같은 요청을 열어도 제출하기 전까지 유지됩니다. 입력기로 한국어 등을 입력하는 동안에는 단축키가
실행되지 않습니다. 백업을 복원하는 등으로 상태 디렉터리가 바뀌면 열린 리뷰가 닫히고, 그 초안과
Tool log는 버립니다.

완료된 결과는 화면에 열린 채로 남습니다. 원격 게시는 **로컬 확정 뒤에**
실패할 수 있습니다. 그러면 양식이 닫히고, 결과는 로컬에 저장됐지만 원격 게시에는 실패했다는 알림이 나옵니다.
판정은 이미 기록되었으니, 다시 제출하지 말고 Settings의 **Push results**
(또는 `artifactize remote push`)로 게시를 다시 시도하세요.

### 나가기와 종료 {#leave-and-quit}

텍스트 필드 밖에서 `q`를 누르거나, Commands에서 **Quit**을 고르거나, 창을 닫으면 종료합니다. 키보드
초점이 편집이나 작업이 진행 중인 Human 리뷰에 있으면 `q`를 눌러도 종료되지 않으니, 먼저 그 작업을
마치거나 취소하세요. Settings가 열려 있을 때도 `q`를 눌러도 동작하지 않습니다.

이 창에서 맡은 Human 요청 중 아직 제출하지도, 담당을 해제하지도 않은 요청이 있으면 어떻게 할지 묻습니다.

| 선택 | 키 | 담당한 요청 |
|---|---|---|
| **Stay** | Esc | 아무것도 바뀌지 않고 앱이 열린 채로 남습니다. |
| **Release and quit** | `u` | 담당을 해제하므로 다른 리뷰어가 맡을 수 있습니다. |
| **Keep and quit** | `k` | 계속 내가 맡은 상태로 남습니다. 담당을 유지해도 판정은 아닙니다. |

종료하면 아직 출력을 내고 있는 도구와 진행 중인 리뷰 작업을 취소합니다. launch 도구가 연 프로그램은
계속 실행되니 직접 닫으세요.

## Settings {#settings}

Settings는 화면 위에 모달 창으로 열립니다. Esc를 누르거나 **Close**를 누르거나 **Settings**
버튼을 다시 누르면 닫히고, 아래 화면은 열기 전 그대로입니다. 열 때마다 계정, 키, 저장소 정보를
다시 불러오며, 팔레트의 **Refresh settings** 명령으로도 다시 불러올 수 있습니다. 탭은
**Providers**, **Remote**, **Limits** 세 개이며, 탭 목록에 초점이 있을 때 ←와 →로 차례로 오갈 수 있습니다.

**Providers** 탭 왼쪽에는 기본 provider(Codex, OpenAI, Anthropic, Gemini)가 차례로 나오고, 그 아래에
직접 추가한 커스텀 provider의 이름과 **+ Custom provider**가 나옵니다. 하나를 고르면 오른쪽에 그
provider의 설정이 나오고, **List models**로 제공하는 모델을 볼 수 있습니다.

- **Codex:** 로그인하지 않은 상태, artifactize가 저장한 토큰과 만료 시각, 읽기 전용
  `ARTIFACTIZE_CODEX_AUTH_FILE`, 또는 저장이 거부된 이유를 보여 줍니다. 저장된 액세스 토큰이 만료되면 다음에 쓸 때 갱신되고, 외부 파일의 토큰이 만료되면 Codex에 다시 로그인해야 합니다.
  외부 파일 모드와 저장 거부 모드에서는 여기서 로그인할 수 없으며, 로그아웃은
  artifactize가 저장한 계정에서만 쓸 수 있습니다. 브라우저 로그인은
  취소할 수 있으며, 로그인 결과가 앱에 자동으로 전달되지 않으면 리디렉션 URL을 붙여 넣을 수 있습니다.
  다른 프로세스가 포트 1455를 쓰고 있으면 앱이 붙여 넣기가 필요하다고 알려 줍니다.
  페이지 로드에 실패하면 브라우저 주소 표시줄에서, 또는 계속 로딩 중이면 개발자 도구 → Network에서
  전체 `http://localhost:1455/auth/callback?code=…` URL을 복사해
  Settings에 붙여 넣은 다음 **Finish sign-in**을 고르세요.
  로그아웃하면 로컬 토큰이 삭제되며, 서버에서 토큰이 폐기됐는지 확인할 수 없으면 경고합니다.
- **OpenAI, Anthropic, Gemini:** 키가 환경 변수에서 오는지, 저장되어 있는지, 없는지를 보여 주며,
  값 자체는 보여 주지 않습니다. 키를 붙여 넣고 **Save key**를 누르면 `artifactize login`처럼
  저장하고, **Remove saved key**로 지웁니다. 환경 변수가 설정되어 있으면 그 키를 먼저 씁니다. 이때
  함께 저장한 키는 보관되지만 쓰이지 않는다고 표시되며, 지울 수도 있습니다.
- **커스텀 provider:** **+ Custom provider**를 누르면 빈 양식이 열립니다. 이름을 정하고, 기본 provider의 별칭(그 provider의 로그인이나 키를 씀)과
  엔드포인트(API, URL, 키(선택 사항)) 중 연결 대상을 고른 다음 **Save**를 누르세요. 필요한 만큼 추가할 수 있고, 목록에서 하나를 고르면 양식에서 바꾸거나
  **Remove provider**로 삭제할 수 있습니다. 엔드포인트에 저장한 키는 보여 주지 않습니다. 키 칸을 비워 두면
  저장된 키를 그대로 쓰고, **No key**를 체크하면 키 없이 저장합니다. eval에서는 `backend`에 이 이름을
  씁니다. [커스텀 provider](../features/agent.md#custom-providers)를 보세요.

**Remote** 탭에서는 리뷰 저장소 연결을 관리합니다. URL과 토큰을 입력하고 공유 수준을 정해 로그인할 수 있으며,
연결 상태 확인, 결과 푸시와 시험 실행, 로그아웃도 할 수 있습니다. **Summary**는 호출 세부 사항,
캡처한 출력, 도구 호출 이력을 빼고, **Full**은 저장된 실행 기록도 보냅니다.
Summary도 리뷰 메타데이터, 추가 결과 필드, 선언된 Runtime 명령과
인자, Agent 실행 경로 메타데이터는 공유합니다. 그 선언에는 경로나 민감한 리터럴이 들어 있을 수 있으며, Summary를 골라도 이런 정보가 자동으로 가려지지는 않습니다. 팀에
필요한 개인정보 보호 수준에 맞춰 공유 수준을 고르세요. 로그아웃은 로컬 설정을 제거할 뿐, **서버
토큰은 제거하지 않습니다**. 저장소 관리자가 [그 토큰을 폐기](../cli/review-store.md#review-store-server)해야 합니다.
[공유와 푸시 동작](../cli/review-store.md#remote-review-store-client)을 보세요.

**Limits** 탭에서는 승인 유휴 유예 시간을 정합니다. 아무도 맡지 않은 승인만 남았을 때 Run이 YELLOW로
종료되기까지 기다리는 시간이며, 바꾸지 않았다면 2분입니다. 그 뒤에 시작하는 Run에 쓸 새 값을 초 단위(0–86400)로
저장합니다. `artifactize limits`와 같은 머신 전체 [설정](../features/others/state.md#sign-off-idle-grace)입니다.

Settings에서 하는 계정과 저장소 관리 작업은 CLI와 같습니다. 자격 증명은
`.artf`에 넣지 않습니다.
