The review bill

Most of every review run is a repeat.

A change touches one file, and the pipeline runs every test again, asks the model about every document again and waits for the same sign-offs again. Agent reviews cost tokens and human reviews cost hours, so re-reviewing everything gets expensive fast.

Artifactize re-reviews only what a change touched, and tells you what it skipped.

How it works

Declare once. Fingerprint every review. Reuse what still holds.

  1. 1

    Declare Artifacts and evals

    A folder with an artifactize.json is an Artifact. It declares the evals that review it and a fingerprint: what that review depends on. Children, mounts and {artifact} references connect Artifacts into one dependency graph, read from these static files without running your code.

    guide/usage/artifactize.json
    {
  "name": "usage",
  "fingerprint": {},
  "evals": [
    {
      "id": "heading",
      "title": "The page has a top-level heading",
      "profile": {
        "kind": "runtime",
        "command": "grep",
        "args": ["-m", "1", "^# ", "page.md"],
        "timeoutMs": 5000
      },
      "payload": {
        "instruction": "Check that {usage} starts with a top-level heading."
      }
    }
  ]
}
  2. 2

    The fingerprint decides

    The built-in content fingerprint, {}, hashes the Artifact's own files; an eval is reviewed again when its Artifact or one it mounts, contains or names changes. Edit one page and status predicts what the next verify will execute, reuse or wait for, and why, without running anything.

    after editing guide/usage/page.md
    $ artifactize status
  guide/terms: WAIT_DEPENDENCY — wait
    Fingerprint changed since Run run-TEblek: dependency usage changed
  intro/heading: PASS — reuse
  usage/heading: STALE — execute
    Fingerprint changed since Run run-TEblek: changed: page.md
Verify actions: will execute 1, will reuse 1, wait 1, blocked 0
  3. 3

    Reuse what still holds

    verify executes only what changed. A reused result names the Run it came from, and the summary counts executed and reused evals by kind. With Agent evals, a usage line adds the tokens that reuse saved.

    terminal
    $ artifactize verify --all
  guide/terms [run-RMMPGS-1]: GREEN
  intro/heading [run-RMMPGS-2]: GREEN (reused from run-TEblek)
  usage/heading [run-RMMPGS-3]: GREEN
Summary: executed 2 (runtime 2, agent 0, human 0), reused 1 (runtime 1, agent 0, human 0)

Three eval kinds, one graph

Tests, models and people review the same Artifacts.

  • Runtime tests · commands

    Any command reviews an Artifact, and its exit code is the verdict: 0 is GREEN. It runs with a private home and temp directory, a timeout and bounded output.

  • Agent LLM review

    One exact model through one explicit backend: an OpenAI or Anthropic API key. It reads through the tools you declare and must answer with a strict GREEN or RED verdict.

  • Human sign-off

    A person claims the request, runs the tools you declared and submits a verdict whose fields your schema validates. With a fingerprint, a sign-off is reused like any other result.

All three share one dependency graph: a RED result blocks what depends on it, and a reused result counts like a fresh one.

Human review in the terminal

Sign off without leaving the terminal.

verify --wait keeps a Run alive while a Human eval waits. artifactize monitor shows Runs as they progress. On a waiting eval, press o and the monitor hands the terminal to artifactize review: claim the request, run the tools its owner declared, fill in the verdict form, and the Run carries on.

Team review store

Centralize the reviews, not the repo.

Every machine keeps its own checkout and state. One artifactize server keeps the verdicts by reuse key and returns the latest, so a change reviewed on Alice's laptop is reused on Bob's and in CI.

  • CI gets a read-only token: it reuses verdicts and never publishes.
  • An outage never turns CI red: verify warns once and reviews locally.
  • By default the store gets a summary: verdicts, owner fields and counters, never argv, output or paths.

Get started

Try it in five minutes.

Artifactize is open source under the Apache License 2.0. Install the 0.4.0 release with Cargo on Linux or WSL 2; the quick start then reviews an example project with no model or API key.

# Linux or WSL 2, with a Rust toolchain and a C compiler
$ cargo install --git https://github.com/lhj6102/artifactize --tag v0.4.0 --locked artifactize
$ artifactize --version
artifactize 0.4.0
