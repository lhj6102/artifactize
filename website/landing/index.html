Artifactize: Evaluation-driven development for people and AI agents.

Declare how each component of your project—code, documents, images, or a running service—is checked by command checks, AI agent reviews, and human sign-offs. Each reviewed component is an Artifact, and the project-wide map of your Artifacts and the inputs each check depends on is the Artifact Graph. When you integrate changes across branches, teammates, or CI, every check whose inputs still match reuses its earlier result.

코드, 문서, 이미지, 실행 중인 서비스 등 프로젝트의 각 구성 요소를 어떻게 검사할지 정하세요. 검사 대상인 구성 요소를 Artifact라고 부릅니다. 명령 실행, AI 에이전트 리뷰, 담당자 승인 중 필요한 방식을 지정하세요. Artifact Graph에서는 프로젝트의 모든 Artifact를 한눈에 볼 수 있고, 각 eval에 어떤 입력이 필요한지도 확인할 수 있습니다. eval에 쓰는 입력이 바뀌지 않으면 이전 결과를 재사용합니다. 브랜치를 병합하거나 팀원의 변경 사항을 반영하거나 CI를 실행할 때도 마찬가지입니다.

At a glance

한눈에 보기

Declare the checks first. Fix what fails until verify turns GREEN.

먼저 eval을 선언하세요. 문제를 고친 뒤 verify를 다시 실행하세요. GREEN이 나올 때까지 반복하세요.

Describe each Artifact in .artifactize/<name>.artf. Reference the Artifacts an eval reads in braces by name—for example, {api} and {spec}—so a change to any of those inputs runs the eval again.

.artifactize/<name>.artf 파일에 각 Artifact를 선언합니다. eval에서 Artifact를 참조하려면 {api}나 {spec}처럼 이름을 중괄호로 감싸세요. 참조한 입력 중 하나라도 바뀌면 해당 eval을 다시 실행합니다.

# .artifactize/api.artf
path = "crates/api/"

[evals.tests]
title = "API tests pass"
profile = { kind = "runtime", command = "cargo", args = ["test", "--locked"] }
payload.instruction = "Run the test suite of {api}."

[evals.matches-spec]
title = "API implementation matches the specification"
profile = { kind = "agent", backend = "codex", model = "gpt-6.2-sol", reasoning = "high" }
payload.instruction = "Review {api} against {spec}. Submit GREEN only when every route matches."
$ artifactize verify --all --wait
  spec/approved    [run-8fK2a1-1]: GREEN (reused from run-3bX9q0)
  api/tests        [run-8fK2a1-2]: GREEN
  api/matches-spec [run-8fK2a1-3]: GREEN
Summary: executed 2 (runtime 1, agent 1, human 0), reused 1 (human 1)

Why teams use Artifactize

팀이 Artifactize를 쓰는 이유

  • Three kinds of checks on one Artifact Graph: combine command checks, read-only AI agent reviews (such as checking api against spec), and human sign-offs. People are asked to sign off only after automated checks pass.
  • 세 가지 방식의 eval을 한 Artifact Graph에서 관리: 명령을 실행해 검사합니다. AI 에이전트에게는 읽기 권한만 주고 리뷰를 맡깁니다. 담당자의 승인을 받는 방법도 있습니다. 예를 들어 AI 에이전트에게 api와 spec이 일치하는지 확인해 달라고 요청할 수 있습니다. 자동으로 실행하는 eval이 모두 GREEN일 때만 담당자에게 승인을 요청합니다.
  • Content fingerprints and shared review store: each check identifies its inputs with a content fingerprint (artifactsum), and a shared team review store lets teammates and CI pull existing results.
  • 입력 내용으로 만든 fingerprint와 팀 공용 저장소: eval마다 입력 내용으로 fingerprint(artifactsum)를 만듭니다. 팀 공용 저장소를 쓰면 팀원과 CI가 모두 이전 eval 결과를 재사용할 수 있습니다.
  • Built for coding agents and people: the Claude Code and Codex plugin lets your coding agent shape declarations and run checks, while the desktop app lets people inspect Runs and sign off.
  • 코딩 에이전트와 사람을 위한 도구: 코딩 에이전트는 Claude Code·Codex 플러그인으로 Artifact를 선언하고 eval을 실행합니다. 담당자는 데스크톱 앱에서 Run을 확인하고 승인합니다.

Get started

시작하기

Try it in five minutes.

5분 만에 써 보세요.

Artifactize runs on Linux, macOS, and Windows and is open source under the Apache License 2.0. You can follow the 5-minute quick start without an AI account or API key.

Artifactize는 Apache License 2.0으로 공개한 오픈 소스 프로젝트입니다. Linux, macOS, Windows를 지원합니다. 빠른 시작 안내대로 하면 5분 만에 써 볼 수 있습니다. AI 서비스 계정이나 API 키는 필요 없습니다.

Download for macOS macOS용 내려받기 Apple silicon and Intel · .dmg Apple silicon과 Intel · .dmg Get it for Windows Windows용 받기 Microsoft Store · x64 Download for Linux Linux용 내려받기 x86_64 · .deb

The desktop app includes the artifactize command. On macOS, open the app once so you can use artifactize in your terminal. On Ubuntu 22.04 or Debian 12+, install the .deb with sudo apt install ./Artifactize-amd64.deb.

데스크톱 앱에 artifactize 명령이 함께 들어 있습니다. macOS에서는 앱을 한 번 열고 나면 터미널에서 artifactize 명령을 쓸 수 있습니다. Ubuntu 22.04 및 Debian 12 이상에서는 sudo apt install ./Artifactize-amd64.deb로 설치하세요.

Install from the command line

명령줄에서 설치하기

# Linux (x86_64, aarch64): installs to ~/.local/bin, no sudo; on x86_64 also the desktop app# Linux (x86_64, aarch64): sudo 없이 ~/.local/bin에 설치, x86_64에서는 데스크톱 앱도 설치
$ curl -fsSL https://artifactize.dev/install.sh | sh
$ artifactize --version
# macOS (Apple silicon, Intel) with Homebrew# macOS (Apple silicon, Intel), Homebrew 사용
$ brew install lhj6102/tap/artifactize
$ artifactize --version
# Without Homebrew: installs to ~/.local/bin and the app to ~/Applications, no sudo# Homebrew와 sudo 없이 CLI는 ~/.local/bin에, 데스크톱 앱은 ~/Applications에 설치합니다
$ curl -fsSL https://artifactize.dev/install.sh | sh

To install both the desktop app and the CLI with Homebrew, run brew install --cask lhj6102/tap/artifactize.

Homebrew로 데스크톱 앱과 CLI를 함께 설치하려면 brew install --cask lhj6102/tap/artifactize를 실행하세요.

# Windows x64 from the Microsoft Store, with the desktop app; then open a new terminal# Windows x64, Microsoft Store에서 데스크톱 앱과 함께 설치한 뒤 새 터미널을 여세요
PS> winget install 9PB6W4LL165D --source msstore
PS> artifactize --version
# Without the Store, in PowerShell with no administrator rights# Microsoft Store를 이용하지 않으려면 관리자 권한 없이 PowerShell을 열어 아래 명령을 실행하세요
PS> irm https://artifactize.dev/install.ps1 | iex

The PowerShell download is not code-signed, so Smart App Control may block it; the Store version is signed by Microsoft.

PowerShell로 내려받는 파일에는 코드 서명이 없습니다. 그래서 Smart App Control이 파일 실행을 막을 수 있습니다. Microsoft Store에서는 Microsoft가 서명한 버전을 받을 수 있습니다.
